# Восстановление читаемого исходного текста

Разделы: граф переходов; IF/ELSE; WHILE; CASE/SELECT; EXIT и пустые ветви;
присваивание аккумулятора; WRITE/WRITELN; литералы и скобки; автоматизация.

## Преобразование графа переходов

Сначала для каждого блока установи входы, выходы и принадлежность
процедуре. Найди все ссылки на метку, включая вложенные ветви, CODE
и переходы из внешнего блока. Удалять метку можно после удаления всех
её использований. Нелокальные переходы к повторному запросу ввода
могут быть существенной частью программы.

Примеры ниже задают семантические преобразования. Совпадение генерации
каждой формы проверяется историческим компилятором.

### Пропуск условной группы

```pascal
_if condition _then _goto 100;
action;
100:
```

Восстанавливай как:

```pascal
_if _not condition _then action;
```

Для сравнения используй противоположный оператор: `=` ↔ `<>`, `<` ↔ `>=`,
`>` ↔ `<=`, когда такая инверсия сохраняет семантику данного типа.
Сокращай двойное отрицание BOOLEAN. Для сложного выражения сперва сохрани
порядок вычисления; перенос вызовов через AND/OR способен менять эффекты.

Преобразование в группу IF требует, чтобы переходы в её середину
не приходили извне. Общую метку продолжения сохраняй, если на неё
ссылаются другие участки.

### Полная альтернатива

```pascal
_if condition _then _(
  first;
  _goto 200;
_);
second;
200:
```

Соответствует:

```pascal
_if condition _then first
_else second;
```

Если THEN заканчивается EXIT, последующие операторы также могут быть
ветвью ELSE. Проверяй, где завершается процедура и что исполняется после
альтернативы. Не удаляй EXIT, если он пропускает реальное продолжение.

Компилятор может оставить безусловный переход после THEN даже при EXIT
внутри этой ветви. Получается недостижимая команда, которая всё же входит
в оригинал. Если такой переход есть в оригинале, оставляй ELSE, который
его порождает; не заменяй его специальной CODE-вставкой. В остальных
случаях убирай ELSE после завершающего ветвь EXIT и переноси последующие
операторы за IF. Ранняя выдача результата и явный ELSE бывают семантически
эквивалентны, но имеют разные размеры. Выбирай форму по машинному образу.

Последовательность альтернатив оформляй как `_else _if`, когда она
действительно является одной цепочкой выбора.

### Объединение вложенных условий

Если единственный оператор THEN является следующим IF, объединяй
условия через AND:

```pascal
_if A _then _(
  _if B _then actions;
_);
```

Записывай как `_if A _and B _then actions;`. Для сравнений сохраняй
необходимые скобки: `_if (x <> _nil) _and (n < limit) _then …`.
Порядок A, B и последующих условий сохраняется.

Перед объединением установи принадлежность ELSE. В частности,
`IF A THEN (IF B THEN X ELSE Y)` имеет другое поведение, чем
`IF A AND B THEN X ELSE Y`: при ложном A первая форма пропускает обе
ветви, а вторая исполняет Y. Наличие операторов между проверками,
внешней метки входа или другой общей ветви также мешает простой замене.

Для условий с вызовами, разыменованием и другими эффектами проверь,
что компилятор в данном контексте AND сохраняет исходное условное
вычисление B только после истинного A. Совпадение сгенерированных команд
доказывает это для проверенного случая; не переноси вывод на произвольный
современный Паскаль-компилятор.

После объединения повторно распознавай обратные переходы. Конструкция
`метка: IF A THEN (IF B THEN (тело; GOTO метка))` превращается в
`WHILE A AND B DO тело`. Эта стадия может открыть циклы, которые
не были видны при анализе каждого IF отдельно.

### WHILE из обратного перехода

```pascal
100:
_if condition _then _(
  action;
  _goto 100;
_);
```

Восстанавливай как:

```pascal
_while condition _do action;
```

Для нескольких действий используй составной оператор. Требуется:

- Условие проверяется перед каждой итерацией.
- Обратный переход завершает тело цикла на всех путях, достигающих
  его конца. Условный GOTO внутри одной ветви не означает автоматически
  WHILE с тем же условием.
- Тело не содержит неучтённых внешних входов, обходящих проверку.
- GOTO к началу из другой ветви сохраняет свою цель либо преобразуется
  с отдельным доказательством эквивалентности.

Сохрани метку перед WHILE, если к ней всё ещё переходят другие участки.
Не переноси через условие операции, стоящие между меткой и IF.
Вложенные циклы удобно преобразовывать от внутренних к внешним,
пересчитывая ссылки после каждого изменения.

Для REPEAT/UNTIL докажи, что тело выполняется до проверки хотя бы один
раз. Бесконечный цикл с несколькими выходами может требовать сохранения
общей метки или CODE, особенно при строгом совпадении упаковки слов.

### CASE, SELECT и наборы условий

По таблице переходов, проверкам диапазона и адресам ветвей различай CASE
и цепочку условных операторов. Семантически похожий SELECT может иметь
другую генерацию. В ЧИСТКЕ L1512 восстановление CASE вместо SELECT
вернуло исходный способ диспетчеризации.

Для ГОСТ цифры имеют коды 0..9: проверки `input@ _in digit` и
`input@ <= '9'` эквивалентны на входных символах. Их генерация может
различаться: IN вызывает проверку диапазона, сравнение проверяет верхнюю
границу непосредственно. Выбирай форму по исходным командам. Для других
кодировок и диапазонов отдельно проверяй необходимость нижней границы.

## EXIT, пустые ветви и самоприсваивания

Убирай EXIT в самом конце процедуры, если он дублирует естественный
возврат и сверка подтверждает ожидаемую генерацию. Обратное преобразование:

```pascal
_if input@ <> chr(125) _then exit;
actions;
```

В конце процедуры его можно записать как:

```pascal
_if input@ = chr(125) _then actions;
```

Если за `actions` есть общее продолжение, такое сокращение уже требует
отдельного анализа. EXIT внутри цикла завершает процедуру, что отличается
от выхода из цикла.

Пустая условная ветвь или самоприсваивание способны соответствовать
реальным командам оригинала. В ЧИСТКЕ сохранены, например:

```pascal
_if _not L1773(root@.types) _then ;
_if _not L1773(l2a1z@.refs) _then l2a1z := l2a1z;
```

Не устраняй их как бессмысленные до анализа результата компиляции.
Недостижимая команда в бинарнике тоже требует объяснения.

## Уже загруженный аккумулятор

Паскаль-автокод допускает присваивание с пустой правой частью:

```pascal
first := _nil;
second := ;
third := ;
```

`second := ;` записывает текущее содержимое аккумулятора без повторной
загрузки. Это позволяет выразить исходную последовательность сохранений.
Обычное `second := _nil` иногда создаёт лишнюю загрузку и увеличивает код.

Докажи, что аккумулятор не изменился между получением значения и записью:
учитывай вычисление адреса, вызовы, проверки и встроенные операции.
Не заменяй все повторные присваивания автоматически: оригинал мог
содержать повторную загрузку. При чтении такого исходника полезен короткий
комментарий о значении A и адресах соответствующих команд.

В ЧИСТКЕ этот приём применён к цепочкам указателей, BOOLEAN и подготовке
дескриптора INPUT. Порядок полей и порядок записей сохраняются.

## Краткая запись вывода

Объединяй соседние вызовы:

```pascal
write('В СТРОКЕ ');
write(line:5);
writeln(' ОШИБКА');
```

В один:

```pascal
writeln('В СТРОКЕ ', line:5, ' ОШИБКА');
```

Аналогично `write(x); writeln;` записывается как `writeln(x);`.
Сохраняй спецификаторы формата каждого аргумента. В проверенном диалекте
ширина целого по умолчанию — 10: явное `:10` можно опустить; `:0`, `:4`
и остальные значимые значения сохраняй.

Объединяй вызовы только в одной последовательной группе операторов.
Строки `IF c THEN write(x); write(y);` не являются двумя безусловными
выводами. Не перемещай вывод через GET/PUT, присваивания, метки,
переходы и вызовы. Учитывай указание другого выходного файла.
При аргументах с побочными эффектами проверь порядок их вычисления
и порядок передачи данных на вывод в данном компиляторе.

CHAR, строка из одного символа и запись `output@ := ch; put(output)`
могут компилироваться по-разному. Переход на WRITE проверяй отдельно:
он способен изменить набор литералов и обращение к АДСИС.

## Литералы, символы и скобки

- Представимые печатные символы ГОСТ записывай в кавычках вместо CHR
  с тем же числом. В CHR аргумент без суффикса десятичный; код в таблице
  часто восьмеричный. Например, ГОСТ 0175 соответствует `chr(125)`.
  Концы строк и другие управляющие коды сохраняй в явной проверенной форме.
- Апостроф внутри символьного литерала удваивается. Не путай кириллические
  и латинские буквы одинакового начертания: сравнивай кодировки.
- Подстрочную десятку записывай символом `⏨` U+23E8.
- Небольшие целые с восьмеричным суффиксом C можно переписать десятичными
  числами, проверив тип и машинное значение. Упакованные 48-битные ALFA,
  дескрипторы и битовые маски обычно удобнее сохранить явно.
- Снимай скобки по приоритетам Паскаля: умножение/AND сильнее сложения/OR,
  отношения слабее арифметики. Для `(a=b) _and (c=d)` скобки существенны.
  Сохраняй порядок вычисления и ассоциативность REAL-выражений.

## Автоматизация преобразований

Для серии правок используй токенизацию со строками, удвоенными
апострофами, комментариями и CODE. Глобальная регулярная замена способна
поменять текст сообщения, директиву или ассемблерный код.

При обходе составных конструкций учитывай `_(`/`_)`, CASE/END,
SELECT/END, RECORD/END, REPEAT/UNTIL и вложенные процедуры. Таблица
входящих ссылок должна относиться к правильной области меток.
Для небольшого числа случаев ручная правка с проверкой обычно надёжнее
нового универсального преобразователя.

Сохрани исходник и сгенерированный бинарник перед преобразованием.
Компилируй после каждой группы однотипных правок. Если заявляешь
«изменился только стиль», проверь равенство всех сравниваемых слов
предыдущей и новой сборок при одинаковых условиях генерации даты.
