# BD и БАНДИТ: восстановленные исходники и устройство базы

Номера зон, адреса, смещения и машинные константы здесь восьмеричные.
Размеры в байтах, число проверенных слов и номера битов — десятичные.
Биты нумеруются от нуля, начиная с младшего.

## Происхождение и точность

В проект импортированы исходники:

- [re-bd.asm](../re-bd.asm), из
  `besm6.github.io/sources/mars/re-bd.asm`;
- [re-bandit.asm](../re-bandit.asm), из
  `besm6.github.io/sources/mars/re-bandit.asm`.

Это восстановленные исходники БЕМШ с макросами и комментариями.
Их соответствие дискам проверено ассемблированием:

| Исходник | Зоны оригинала | Совпадение |
|---|---|---|
| re-bd.asm | 2148:01026, 2248:01026 | 1024/1024 слова, 6144/6144 байта |
| re-bandit.asm | 2148:01027, 2248:01027 | 1024/1024 слова, 6144/6144 байта |

SHA-256 исходников:

```text
re-bd.asm      a5623d153520fbd8b0f0e67330ee935389d98253df04ce0e0a84f3a9888ac780
re-bandit.asm  6244414dca995012ecf72fcd0daa4239f5feb048bc474b5e93ed7b0fc1d49e6e
```

Повторение: `make checkbanditasm`. Скрипт
[tools/build-bandit.py](../tools/build-bandit.py) использует исторический
макро-БЕМШ и РВС, проверяет нулевое число ошибок и результат ЗОНГП.
Исходные диски проверяются по SHA-256 до и после работы.
Артефакты находятся в `build/bandit-asm/`: исходные и собранные зоны,
листинги с таблицами всех меток, `comparison.json` и общий `report.json`.

Объект следует размещать командой **НАЗ 000001**. `СТАРТ 1` и
`УПОТР БАНДИТ-1(4)` задают относительные смещения; загрузка на 074001
добавила бы базу к части констант и адресов. Пустые строки при подготовке
колоды пропускаются: БЕМШ воспринимает пустую карту как отсутствие операции.
При импорте удалены хвостовые пробелы.

## Диспетчер BD

BD работает с базой **066000**, М13 указывает на начало листа.
Вход 0007 переносит страницу в рабочую область через Э75 и устанавливает
М13; вход 0004 рассчитан на базу 072000. `START` вызывает резидентный
сканер 76016, читает массив типизированных параметров через 76015 и
выбирает обработчик по таблице `BDdec`, **00472–00521**.

Таблица содержит NEW, OPEN, OBTAIN, OBT, PUT, DELETE, DEL, MODIFY, MOD,
GET, ИНФ, КТЛ. Опции NEW: СИС, ТАБ, БУФ; опции записи: ДЛВ, СИМ, СЛО.
Макросы `opt`, `case`, `decod` разбирают параметры, `prep` проверяет
сигнатуру БАНДИТ и готовит общий блок параметров, `bandt` вызывает движок.
Возврат в ПУЛЬТ идёт через 76002, печать — через 76005.

`rdsys` читает **40:027**, по умолчанию в лист 36. Рабочие листы:
каталог — 34, буфер остальных зон базы — 33. Адрес исходного текста
по умолчанию **010000**. Для новой базы исходные значения размещения —
**27:0000**, длина **020** зон. NEW допускает явное размещение и получение
дескриптора файла через архивный поиск 76006.

OPEN загружает БАНДИТ. Остальные операции используют уже загруженный
образ; `BD КТЛ` до OPEN закономерно даёт «СТЕРТА БД-СИСТЕМА».
После `BD OPEN КТЛBD` каталог выводится штатно; детали и все 21 имя
приведены в [bd-catalog.md](bd-catalog.md).

PUT с ДЛВ вызывает запись фиксированной длины. По умолчанию PUT ищет
последовательность **0172, 0175**; СИМ меняет символьный ограничитель,
СЛО выбирает ограничитель-слово. Исходник сохраняет отличие между
байтовым/двухбайтовым и полным 48-битным ограничителем.

## Размещение движка и интерфейс

При обычном OPEN база БАНДИТ — **074000**, М4 содержит её адрес.
Все смещения в следующих таблицах прибавляются к этой базе.
Сигнатура «БАНДИТ» находится в **0001**, слово 0002 содержит **01162**.
Код, переменные, сообщения и константы занимают **0001–1161**.
В **1162–1762** находится заполнение; **1763, 1767, 1773, 1777** —
сохранившиеся остаточные значения. Они включены в точное сравнение зоны.

| Смещение | Параметр / состояние |
|---|---|
| 0003 `nuzzzz` | устройство и начальная зона текущей базы |
| 0004 `rtlen` | число зон |
| 0005 `curdsc` | текущая ссылка на запись |
| 0006 `bdbuf` | адрес буфера обычного блока |
| 0010 `key` | шестисимвольное имя; ноль выбирает адресный доступ |
| 0011 `erradr` | адрес обработки ошибки у вызывающей программы |
| 0012 `adescr` | адрес ячейки, содержащей ссылку на запись |
| 0013 `myloc` | адрес пользовательского массива |
| 0014 `bdtab` | адрес первого блока с каталогом |
| 0015 `mylen` | длина/ограничение пользовательского массива |
| 0024 `savm4` | сохраняемый М4 вызывающей программы |
| 0026 `root` | полный дескриптор размещения базы |
| 0027 `arg` | дополнительный параметр операции |
| 0035–0037 | ссылка, позиция и имя при обходе каталога |
| 0043 `arch` | главный каталог баз, **01400030**, то есть одна зона 40:0030 |

| Вход | Тело процедуры | Назначение |
|---|---|---|
| 0016 | `open` 0271 | Найти именованную базу в главном каталоге и открыть |
| 0017 | `putfix` 0454 | Записать массив заданной длины |
| 0020 | `get` 0741 | Прочитать запись или её служебные сведения |
| 0021 | `delete` 0343 | Удалить запись |
| 0022 | `modif` 0662 | Вход MOD; особенности потока управления — ниже |
| 0023 | `newbd` 0664 | Создать базу и запись о ней в главном каталоге |
| 0031 | `rdroot` 0304 | Открыть базу по уже заданному root |
| 0032 | `init` 0440 | Инициализировать состояние/буфер |
| 0033 | `putvar` 0101 | Определить длину по ограничителю и записать |
| 0034 | `info` 0045 | Обход каталога и получение его параметров |
| 0044 | `entr44` 1016 | Читать очередной фрагмент по ссылке adescr |

Внешние входы сохраняют адрес возврата из М16 в A перед общим входом.
`enter`/`init` сохраняют М5, М6 и РАУ, устанавливают РАУ=3;
`exit` восстанавливает состояние и М4. Код использует М5/М6 как внутренние
продолжения. Это интерфейс через общий блок параметров.

Дата в служебном заголовке, 0030: **171167**; отдельной проверкой времени
создания образа эта строка не является.

## OPEN и адресация

`chkdsk` (**0273**) получает номер тома устройства 40 через Э50 0105
и сравнивает его с **0x2048**. В обычном пути `root=01400030`.
`open2` читает запись с именем `key` из главного каталога и копирует
содержащийся в ней дескриптор размещения в `root`. Затем `rdroot`
повторяет открытие для выбранной базы.

В ветви `is2048` (**0277**) сначала сохраняется исходное значение в root,
после чего в A добавляются через ИЛИ биты устройства 57. Таким образом,
фактическое устройство первого чтения становится 57, а проверяемый ключ
root сохраняет устройство 40. Это точный порядок инструкций дискового
образа; работоспособность этого пути зависит от заголовка подключённого
каталога. Проверенные здесь пробы выполнялись с томом 2068 на устройстве 40.

`chkcnt` (**0306–0331**) выделяет младшие 18 бит как адрес устройства/зоны,
остальные — как длину. Перед чтением используется буфер bdtab; совпадение
слова 0 с root и нулевое слово 2 позволяют использовать уже прочитанный
первый блок. После чтения проверка повторяется. Ошибка — «ЗАТЕРТ 1Й ЛИСТ БД».
Начало каталога берётся из младших десяти бит слова 3.

## Блоки, записи и свободное место

Блок содержит **02000 слов**. Во всех блоках слово 0 — ключ базы root,
слово 2 — номер блока относительно её начала. Слово 1 содержит:

- биты 0–9: последний индекс таблицы слотов;
- биты 10–20: нижнюю границу области тел записей;
- бит 21: признак освобождённых слотов, требующих поиска свободной ячейки.

Слоты начинаются со слова 4 и растут вверх. Тела записей размещаются
сверху вниз. При удалении тела уплотняются, адреса в оставшихся слотах
корректируются. Поэтому ссылка на запись сохраняет номер слота.

```text
ссылка = (slot << 10) | block
слово слота = offset | (length << 10) | (next_reference << 20)
```

Сдвиги здесь десятичные. offset и length занимают по десять бит;
следующие двадцать бит задают ссылку на продолжение длинной записи.
`rdelt` (**0156–0203**) выбирает блок и слот, проверяет ключ блока,
извлекает адрес тела, длину фрагмента и ссылку продолжения.

Первый блок дополнительно хранит каталог пар `(имя, ссылка)`.
В конце первого блока находится таблица свободного места по каждому
блоку: `frebas = bdtab + 02000 - rtlen`. Перед ней хранится число
занятых слов каталога. `alloc2` уменьшает счётчик свободного места
при выделении, `delet1` увеличивает его при освобождении.
Поле 1777 в однозонном КТЛБД является именно таким счётчиком.

`putfix`/`alloc2` (**0454–0557**) резервируют тело, служебное слово и
слот. Существующие пустые слоты используются повторно. Если текущий блок
не подходит, `notfit` перебирает остальные по таблице свободного места.
`long`/`fragm` (**0616–0653**) разбивают длинную запись и связывают фрагменты.
В слоте длина включает служебное слово первого фрагмента.
GET пропускает это слово, копирует данные и следует цепочке.
Вход 0044 позволяет читать отдельные фрагменты, обновляя adescr.

При свободном имени пара добавляется в каталог, его длина увеличивается
на два слова. При совпадении имени `нашли` (**0577**) удаляет только что
созданную запись и возвращает ошибку «ЭТО ИМЯ УЖЕ ЕСТЬ»: обычный PUT
сохраняет прежнюю именованную запись.

`delete` находит имя, сдвигает пары каталога, уменьшает его длину,
освобождает тело и слот и проходит все продолжения. После уплотнения
производятся записи изменённых блоков и первого блока.

## Метаданные и выдача GET

`date` (**0562–0576**) формирует первое слово записи:

```text
metadata = packed_date | ((account >> 30) << 15) | original_length
```

`packed_date` — выбранные маской **0377774000000** биты результата Э50 0114,
собранные СБР в старшие позиции. Поля занимают соответственно 15, 18 и
15 бит. Формат и проверенные значения описаны в [bd-catalog.md](bd-catalog.md).

Младшие два бита arg выбирают вариант GET:

| arg | Выдача |
|---|---|
| 0 | Данные в myloc, с проверкой допустимой длины при ненулевом mylen |
| 1 | Распакованная дата в A, маска `dtmsk1` |
| 2 | Исходная длина в A |
| 3 | Адрес строки с именем, длиной, шифром и датой |

ИНФ и КТЛ ПОЛН используют вариант 3. Год в строке имеет одну цифру.
Независимая проверка на частных копиях томов дала:

```text
арх сисбиб,40,0
bd open ктлBD
bd инф ктлбд
ИМЯ         ДЛИНА  ШИФР ДАТА
КТЛБД       00001  0353 06096
bd инф бд7154
ИМЯ         ДЛИНА  ШИФР ДАТА
БД7154      00001  0353 08096
```

## Создание базы, MOD и границы проверки

NEW создаёт запись о размещении в главном каталоге, формирует первый
блок новой базы, пустой каталог, таблицу свободного места и заголовки
остальных блоков. `newbd2` использует myloc как размер запрашиваемой
области каталога; BD передаёт туда
`maxzon << 6`. При myloc < 02000 исходный размер сохраняется, иначе
подставляется 01000. Длина базы и её адрес поступают через arg.

В MOD присутствуют две особенности, сохранённые точным исходником:

1. BD, смещение **00470**, вызывает `ПВ 0022(М4)` при подготовленном
   базовом М4. В трассе: **66470 → 74022**, М4 получает адрес возврата
   **66471**. Следующий `ПБ 0662(М4)` идёт в **67353**, после чего возникает
   АВОСТ 000022. Для обычных вызовов `bandt` используется М16.
2. БАНДИТ, **0662–0663**, выполняет `init`, сохраняет М6 и непосредственно
   продолжает `newbd` в **0664**. Самостоятельное тело замены существующей
   записи в этом месте отсутствует.

На частной базе команда `BD MOD BETA 10000` воспроизводит этот сбой.
Побитное совпадение подтверждает присутствие обоих участков в дисковых
образах. Машинный код этих участков воспроизведён точно.

### Рабочий MODIF в частной версии

`make bdprivate` создаёт **build/bd-private/2068**. Частный BD вызывает
MOD через М16 и использует буфер 032. В БАНДИТ сохранён вход 0022;
слово 00663 передаёт управление вставке [bandit-mod.inc](../bandit-mod.inc)
в заполнении с 01162. Хвост 01763–01777 и адреса остальных процедур
сохранены. Исторические исходники собираются отдельно без изменений.

MODIF повторяет путь GET: поиск по имени или adescr, проверку mylen,
пропуск служебного слова первого фрагмента, обход цепочки через rdelt.
Цикл копирует слова из myloc в adata. Каждый изменённый блок записывается
через Э70 перед переходом к следующему фрагменту. Завершение — rtexit.
Длина, метаданные, слоты, ссылки и свободное место сохраняются.

Сборщик проверяет допустимые области изменений и устанавливает командные
теги вставки. `make checkbdmod` проверяет замену однословной записи,
цепочку 1088 слов, GET после MOD и повторного открытия, адресный доступ,
отсутствующее имя, недостаточный mylen, нулевой adescr и пустой слот.
Проверяются сохранность соседей, метаданных, структуры, каталога и
эталонных томов. Отчёт и трассы находятся в **build/bd-mod/**.

Обработчик `err` возвращает числовой код в A и адрес трёхсловного
сообщения через М16 в пользовательский erradr. Основная таблица содержит
16 сообщений: нулевой ключ, повреждённый блок, удалённая/отсутствующая запись,
отсутствующая база, переполнение, занятое имя, отсутствие ограничителя,
превышение ДЛВ, пустой каталог и границы обхода. Есть также пути с кодами
20 и 21 (десятичными), выходящие за эту таблицу; BD умеет печатать
числовую диагностику `ОШ.N=`.

### Проверенные операции и конфликт рабочего листа

`make checkbandit` выполняет два сценария [tests/bandit.py](../tests/bandit.py).
Все изменяемые тома копируются в частный каталог с собственным HOME.
Создаётся база **30:0200**, длина **4** зоны; запись о ней заводится
в частной копии КТЛБД после удаления старого имени ВОСЬМР.

Первый сценарий сохраняет оригинальный код: NEW, OPEN, PUT и GET
одного слова, повторный PUT, DELETE, отсутствие удалённой записи,
ИНФ и обход каталога. Полученное слово записывается ещё раз под именем
BETA; содержимое итоговой записи проверяется непосредственно на диске.
В конце проверяется ожидаемый сбой MOD.

Во втором сценарии проверена запись **02100 слов (1088 десятичных)**,
её чтение и удаление. Для каждого слова результата GET проверяется
запись в пользовательский массив; конечный каталог содержит только BETA.
Этот сценарий требует переноса буфера: стандартное значение BD,
**026:0546 = 033**, выбирает лист **066000–067777**, где находится сам BD.
При обмене с ненулевым блоком базы движок перезаписывает диспетчер,
и возврат приводит к аварии. В частной копии проверяемо заменяется
**026:0546: 033 → 032**, выбирая свободный лист **064000**.
Это изменение окружения явно отмечается в отчёте; оригинальные
`re-bd.asm`, диски 2148/2248 и собранный 2068 сохраняются.

Остались дополнительные граничные сценарии: исчерпание места,
символьные ограничители и все режимы адресного обхода. Основные операции
и цепочки длинных записей проверены; исторический MOD имеет установленный дефект; частная версия исправлена.
