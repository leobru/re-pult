# СТРУК: структура Паскаль-программы

СТРУК из каталога ПУЛЬТа находится в **зоне 01073** томов **2148 и
2248**. Обе копии совпадают целиком: одна зона, 1024 слова по 48 бит.
В заголовке записана дата **11.11.86**. Сохраняемая программа занимает
**00000–01464**, вход **00007**; слово 00005 содержит конец **01465**.
Зона 074 относится к следующей записи каталога, РЕЗРВ3.

Восстановленный исходник — [pascal/struk.pas](../pascal/struk.pas).
Майский и декабрьский компиляторы Паскаля-автокода воспроизводят **все
1024 слова**, включая заголовок и остаток зоны. Дату задаёт окружение
компиляции; сгенерированные слова не исправляются.

## Запуск и результат

В ПУЛЬТе:

```text
струк
500101 1 Т
```

На приглашение ` ++> ` вводятся:

```text
НАЧАЛО ЧИСЛОЗОН [/НАЧАЛОВЫВОДА ЧИСЛОЗОНВЫВОДА] [Т]
```

НАЧАЛО имеет вид `NUZZZZ`: логическое устройство N и начальная зона.
Числа накапливаются в восьмеричной системе. После первого числа допускается
буква В, например `500101В 1`. Проверка номера устройства/зоны ограничена
диапазоном **100000–677777**, длина должна быть ненулевой. Предикат цифры
принимает также 8 и 9; запись `value*8+digit` сохраняет эту особенность.

Без Т печатается порядок объявлений с отступами по уровню вложенности.
С Т дополнительно выводится список по алфавиту с именами внешних процедур.
Корень программы при сортировке остаётся на месте и исключается из второго
списка. Если в таблице только программа, второй список сохраняет эту запись.

Например, [nested.pas](../tests/struk/nested.pas) содержит ZETA, вложенную
в неё INNER и функцию ALPHA. Существенная часть выдачи:

```text
*1* TEST       СТР=0001-0009-0009
*2* ZETA   (П) СТР=0003-0006-0006
*3*    INNER  (П) СТР=0004-0005-0005
*2* ALPHA  (Ф) СТР=0007-0008-0008

* * *   СПИСОК ПРОЦЕДУР/ФУНКЦИЙ   * * *

*2* ALPHA  (Ф) СТР=0007-0008-0008
*3* INNER  (П) СТР=0004-0005-0005  ZETA
*2* ZETA   (П) СТР=0003-0006-0006
```

Три номера после СТР — строка объявления, строка начала тела и строка
закрывающего END. Внешний блок имеет уровень 1. Для FORWARD после номера
объявления выводится `+`; заголовок и последующее определение остаются
отдельными записями. Имена усекаются до шести символов и дополняются справа
пробелами. Реальная выдача использует общие для латиницы и кириллицы коды ГОСТ.

В начале запроса можно передать скопированное приглашение `++> `: ветвь
01357 пропускает четыре символа, если первый — `+`. При достижении ETX
на приглашении печатается `<*> ВОЗВРАТ <*>`, затем выполняется переход
в ПУЛЬТ через 76002. При длинном отчёте форматтер запрашивает `ИДТИ?`;
пустой ответ продолжает выдачу.

Отдельные запросы ПА, ПП и ППН устанавливают слово **76013** в 2, 3 и 1.
Нераспознанное имя режима вызывает `ОШИБКА`. Это настройки резидентного
вывода ПУЛЬТа, описанные в [разборе СБОЙ](sboy.md).

## Что разбирается

NextWord (00537) ищет подчёркнутые ключевые слова Паскаля. ReadWord (00346)
возвращает первые шесть букв/цифр. Формы `_(` и `_)` представляются как
`BEGIN ` и `END   `. SkipSpaces (00322) пропускает пробелы, концы строк и
комментарии, сохраняя номер строки. SkipComment (00267) рекурсивно обрабатывает
вложенные комментарии. NextWord пропускает также литералы в кавычках. Цикл пропуска ищет
закрывающую кавычку; отдельной проверки конца текста внутри этого цикла нет.

ParseBlock (01025) создаёт запись для имени программы, процедуры или функции.
После имени подпрограммы пропускаются параметры и имя возвращаемого типа.
Знак `+` в позиции FORWARD завершает обработку этого заголовка. При встрече
PROCED/FUNCTI рекурсивно вызывается ParseBlock с увеличенным уровнем.

Ключевые слова CONST, TYPE, LABEL, VAR, FILE, OF, RECORD, ARRAY, SET, CASE,
END, NIL и PACKED допускаются в описаниях. При BEGIN запоминается строка,
а SkipBody (01005) балансирует вложенные BEGIN/SELECT/CASE и END. Это
структурный лексический разбор: он не строит таблицу типов и не проверяет
ссылки между объявлениями. Неизвестное ключевое слово в описаниях вызывает
ошибку 2. После тела главной программы проверяется точка.

## Таблица в памяти

Глобальные поля расположены от М1 следующим образом; адреса восьмеричные:

| Смещение | Поле |
|---|---|
| 00012 | Вывод отчёта в файл |
| 00013 | Запрос алфавитного списка |
| 00014 | Сохранённая граница кучи / первая запись |
| 00015 | Текущий номер строки |
| 00016 | Рабочий счётчик |
| 00017 | Число записей |
| 00020 | Упакованное имя режима / рабочее слово |
| 00021 | Признак функции для следующей записи |
| 00022 | Служебный указатель кучи Паскаля |

Allocate (00250) использует NEW для последовательных восьмисловных записей:

| Слово | Поле |
|---|---|
| 0 | Имя |
| 1 | Имя внешнего блока |
| 2 | Уровень вложенности |
| 3 | Строка объявления |
| 4 | Строка начала тела |
| 5 | Строка последнего END |
| 6 | FORWARD, BOOLEAN |
| 7 | Признак функции, 0/1, сравниваемый с целым нулём |

SETUP сохраняет начальную границу, ROLLUP перед каждым запросом освобождает
все записи предыдущей программы. Параметр K4 задаёт **010000 слов** кучи.
При NIL после NEW печатается `КОНЧИЛОСЬ МЕСТО` и восстанавливается граница.

SortRows (00466) выполняет пузырьковую сортировку записей после корня.
Greater (00434) отдельно сравнивает старший байт ALFA и оставшиеся 40 бит;
при перестановке копируются все восемь слов. Цикл повторяется до прохода
без обменов. PrintTable (00635) печатает порядок с отступами либо алфавитный
список; в последнем случае для уровней больше 2 дописывается внешний блок.

PrintLine (00613) выдаёт четыре десятичные цифры через CHR и PUT, включая
ведущие нули. В этой процедуре действует локальный M-: деления на 1000,
100 и 10 компилятор заменяет умножением на обратные значения. Остальной
исходник использует M+; он сохраняет библиотечную коррекцию целочисленного
умножения при вычислении отступов и адресов.

## Дисковый отчёт

```text
500101 1 /500103 1 Т
```

BindInput (00204) задаёт дескриптор INPUT через **75211–75212**; после него
выполняется RESET. BindOutput (00216) устанавливает **75203, 75223, 75204**
и открывает OUTPUT через REWRITE. Проверка `saved-report` записывает отчёт
на устройство 50, зона 0103, в частный диск.

При записи в файл NewLine (00604) выдаёт байт 0175. Перед двумя списками
пишутся управляющие последовательности системы ТИРАЖ:
`ЬЬМLУЬЬЗ` и `ЬЬЛЬЬЗ` соответственно, в кодировке ГОСТ.
В первой последовательности L — латинская буква.
FlushReport (00231) дописывает 0172, 0175 и шесть пробелов, проверяет
достижение заданной границы OUTPUT и при необходимости записывает
последнюю зону через Э70 75223. Затем восстанавливается OUTPUT на
барабане 27 с адреса 270000, протяжённость одна зона.

Проверка сравнивает и терминальную выдачу, и весь частный диск после
оригинала и пересборки. Для остальных сценариев подтверждено отсутствие
записи в диск с исходным текстом.

## Ошибки

Fail (00166) переоткрывает OUTPUT, печатает номер и строку, вызывает
**74070 → 75251** для выдачи контекста текущего INPUT через СБОЙ и
нелокальным переходом возвращается к приглашению 01345.

| Код | Условие |
|---|---|
| 0 | Первое ключевое слово не PROGRA |
| 1 | Конец текста при поиске очередного слова |
| 2 | Неизвестное ключевое слово в описаниях |
| 3 | Незакрытый комментарий; предварительно `НЕЗАК.КОМ.` |
| 4 | После END главной программы отсутствует точка |

Ошибки числового запроса вызывают `ОШИБКА В ЧИСЛЕ` и возврат к приглашению.

## Компоновка и проверка

Массив литералов **00011–00165** содержит 109 слов. Первые процедуры идут
с **00166**, главная программа — **01335**, служебный хвост — **01446–01464**.
Таблица всех 18 входов и размеров хранится в `comparison.json` и проверяется
[tests/struk-layout.py](../tests/struk-layout.py).

| Fail | 00166 | 0016 |

| BindOutput | 00216 | 0013 |
| FlushReport | 00231 | 0017 |

| SkipComment | 00267 | 0033 |
| SkipSpaces | 00322 | 0024 |
| ReadWord | 00346 | 0066 |
| Greater | 00434 | 0032 |

| ReadAddress | 01222 | 0060 |

 Сборка сохраняет исходные
переходы после EXIT и последней ветви SELECT; сокращение SELECT в IF меняет
часть этих команд.

```sh
make struk
make checkstruk DISPAK=dispak
```

`checkstruk` последовательно использует компиляторы **17.05.88** и
**09.12.88**. Декабрьская копия подключается с проверяемыми исправлениями
из `tools/volume2068.json`. Каждый прогон сравнивает всю зону и выполняет
20 сценариев: обычные и вложенные блоки, комментарии, FORWARD, длинные имена,
исходный порядок, сортировку, параметры запроса, сохранение отчёта, режимы
вывода, выход и ошибки. Исходные тома проверяются по SHA-256 до и после.

`tests/struk/compile-date.c` подменяет только календарное преобразование
`localtime()` на **11.11.86**. Учёт времени и тайм-ауты остаются рабочими.
Образ после компиляции не модифицируется и не маскируется при сравнении.

Артефакты: `build/struk-rebuild/` и `build/struk-rebuild-december/`.
В каждом каталоге находятся `original.bin`, `generated.bin`, полные
листинги `.lst`, таблицы литералов, протокол компиляции, ввод/вывод сеансов
и `comparison.json`. Для `saved-report` сохраняются также двоичная зона
отчёта и её декодированный текст.

SHA-256 полного оригинала и обеих пересборок:
`a46f7a90f0d3e4de4f9f3cb299e299dad236619ba5bee98e3a1042a4d4b108d1`.
