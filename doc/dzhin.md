# ДЖИП: загрузчик ДЖИН и восстановление исходного Паскаля

Файл **ДЖИП**, зона **01070** обоих исходных томов, содержит
Паскаль-программу с собственным именем **ДЖИН** и датой **07.12.87**.
Она подключает области АРФА `ДЖИН.РАБОЧ` и `ДЖИН.ПРОГР`, затем
загружает из второй области пять зон и передаёт управление загруженной
программе. Машинный образ самой программы занимает **194 слова**,
адреса **00000–00301**. Поле **00005 = 0302** задаёт начало стека.

Для этого образа восстановлен
[исходник на Паскале](../pascal/dzhin.pas), который компилируется
в **полностью идентичные 194 слова**. Совпадают заголовок, константы,
дескрипторы, все инструкции и служебные прологи. После компиляции
генерируемые слова не исправляются.

Зоны, адреса, номера устройств и экстракоды далее восьмеричные.
Количества слов — десятичные; отдельные значения слов — шестнадцатеричные.

## Сборка и проверка

```sh
make dzhin
python3 tests/dzhin.py --dispak=/home/leob/git/dispak/build/dispak/dispak
```

[Разметка](../syms/ДЖИП.sym) создаёт `build/ДЖИП.lst`;
полный дамп сохраняется в `build/ДЖИП.dump`.
[Проверочный скрипт](../tests/dzhin.py) использует временные копии
2248/2068, частный архив 2345 и отдельные каталоги АРФА.
dispak запускается через `tools/run-dispak.sh`, с HOME внутри `build/`.
Исходные тома проверяются по SHA-256 и остаются неизменными.

Использован восстановленный компилятор **ПАСКАЛЬ-АВТОКОД 9.(09.12.88)**
из 2068 и штатный системный автокод ИТМ. Приказ компиляции:

```text
ПАС ДЖИН - ПА ЗОНГП 500300 1
```

Компилятор пишет `МАХАDR=00302`, образ сохраняется в зону 0300
частного тома 2345. Полученный образ сравнивается с обоими исходными
томами и с копией ДЖИП в 2068.

В заголовок компилятор помещает текущую дату. Для побайтового
воспроизведения слова **00002** тест подставляет **07.12.1987** через
маленькую библиотеку [compile-date.c](../tests/dzhin/compile-date.c),
переопределяющую `localtime()` в процессе эмулятора. Функции измерения
времени и тайм-ауты продолжают работать обычно; системные часы не меняются.
Без этой настройки можно проверить код с текущей датой:

```sh
python3 tests/dzhin.py --dispak=/home/leob/git/dispak/build/dispak/dispak --current-date
```

В этом режиме разрешено различие исключительно в слове **00002**.
С исторической датой различий в программе **нет**. SHA-256 её
1164 байтов:

```text
5ed6ee7a3f8ba31eb197556f52ccefb748406c14485f6652d01be5066ffcc3f8
```

Артефакты — `build/dzhin-rebuild/`: `generated.bin`, два файла
`*-program.bin`, `comparison.json`, вывод и трассы компиляции и запусков.
Скрипт также проверяет одинаковую диагностику исходной и восстановленной
программ при отсутствии архивной области.

## Граница программы и содержимое всей зоны

Оба исходных тома содержат одинаковую зону ДЖИП. В ней:

| Адреса | Содержимое |
|---|---|
| 00000–00010 | заголовок и вход АДСИС |
| 00011–00045 | константы и строки |
| 00046–00262 | процедуры и главная программа; внутри лежат дескрипторы Э70 |
| 00263–00301 | служебные прологи и восстановление базы М2 |
| 00302–01777 | остаточное содержимое вне машинного образа ДЖИН |

Совпадение 194 слов относится ко всему образу, ограниченному словом
**00005**. Остальные **830 слов** не входят в программу. В них находятся
фрагменты с обращениями к абсолютным адресам за пределами зоны и таблицы
другого кода. При повторной компиляции даже этот остаток совпал почти
целиком; различаются только **00614, 00631, 00641**:

| Адрес | Исходная зона | Зона после компиляции |
|---|---|---|
| 00614 | `0x0000000010ca` | `0x0000000010d2` |
| 00631 | `0x0ca000000000` | `0x0d2000000000` |
| 00641 | `0x0000000040d6` | `0x0000000040de` |

Сходство этого остатка и величины различий согласуются с сохранением
рабочей памяти транслятора при записи полной зоны. Точный смысл трёх
полей не установлен. Полная зона из 1024 слов побайтово не воспроизведена;
исполнимый образ программы воспроизведён целиком.

## Вызов из ПУЛЬТа

Приказ `ДЖИН` обрабатывает ПУСК **01337–01342**. Он читает АДСИС
из u40 z006 в лист 36, устанавливает в ячейке **6** загрузочную
команду Э70 и передаёт ей управление. Команда читает u40 z070
в лист 0; продолжение по **7** уже принадлежит ДЖИН.
Обычный Паскаль-вход **00007–00010** обращается к **74003**,
а затем к главной программе **00257**.

`ДИАЛОГ` также читает эту зону, помещая её в лист **012** вместе
с загрузкой ЭХОЛОТ в листы 0–3. Собственные команды ДЖИН имеют
абсолютные адреса; прямой запуск входа 7 с базой листа 012 из этого
факта не следует. Взаимодействие с ЭХОЛОТ требует отдельного разбора
ЭХОЛОТ.

## Процедуры

| Вход | Восстановленное имя | Назначение |
|---|---|---|
| 00046 | `fail(err)` | текст ошибки АРФА и возврат в ПУЛЬТ |
| 00071 | `loadProgram` | чтение пяти зон и запуск |
| 00110 | `detach(u)` | освобождение логического устройства через Э72 |
| 00117 | `volume(u)` | запрос номера тома/идентификатора и преобразование BCD |
| 00147 | `archive` | вложенная функция: идентификатор области по имени |
| 00166 | `attach` | подключение рабочей и программной областей |
| 00257 | главная программа | `attach; loadProgram` |

`fail`, `loadProgram`, `detach`, `volume`, `attach` находятся на уровне 2;
`archive` вложена в `attach` и использует уровень 3. Прологи **00265**
и **00271** устанавливают базы соответственно М2 и М3. **00263**
восстанавливает М2 после вызова внешней для текущего уровня процедуры.
Главный пролог **00275** инициализирует Паскаль через **74251/74313**.

## Запрос области АРФА

В кадре `attach` выделены:

| Смещение от М2 | Содержимое |
|---|---|
| 3 | прежний идентификатор устройства / статус |
| 4 | слово `КЛЮЧАР` |
| 5 | маска допустимых устройств |
| 6 | информационное слово АРФА |
| 7–11 | три слова имени области |

М7 получает адрес информационного слова. Для запроса используется
**`0x2c0000000008`** — операция АРФА **013**, имя в строковом виде.
Перед Э63 в сумматор загружается `КЛЮЧАР`, а РМР обнуляется.
**00156** вызывает **Э63 (М7)**; возвращённый в A идентификатор
становится результатом функции. Код ответа из М16 проверяется отдельно.
При ненулевом коде вызывается `fail`.

Три слова имени в памяти декодируются как:

```text
ДЖИН.РАБОЧ/4177..;
```

Для второй области первые два слова заменяются, а третье сохраняется:

```text
ДЖИН.ПРОГР/4177..;
```

Это точные строки, передаваемые интерфейсу АРФА. Суффикс сохранён
в исходнике как машинная константа; его историческая семантика здесь
не подменяется правилами современного эмулятора.

## Подключение устройств 41 и 42

Рабочая маска **`0x006000000000`** разрешает два устройства: **041**
и **042**, при нумерации битов АРФА от устройства 030 в старшем разряде.
Сначала программа сравнивает результат `volume(33)` с идентификатором
рабочей области; десятичное 33 в исходном Паскале означает устройство 041.

Если идентификаторы равны, рабочее устройство уже подключено.
Иначе ненулевое прежнее назначение освобождается. `detach` сдвигает
номер устройства в информационное слово
**`0x400fc0000000`** и выполняет **Э72 3(М2)** (**00115**).
Затем АРФА вызывается с **`0x280000000008`**, операцией **012**,
дозаказом области с доступом для записи.

Перед этим вызовом `available := available` намеренно загружает маску
в A. Следующая пара `мода; сда 160` сдвигает её на 48 разрядов:
A обнуляется, маска попадает в РМР. Удаление самоприсваивания изменяет
параметры вызова. В запросе идентификатора вместо `мода` стоит `сч 0`,
поэтому тот же сдвиг даёт нулевой РМР.

После рабочей области **00224–00225** удаляют бит 041 из маски:
константа **`0x004000000000`** инвертируется через все единицы по
**74000** и применяется операцией И. Для программной области остаётся
только устройство **042**. Повторяются проверка идентификатора и
освобождение старого назначения. В дозаказе используется
**`0x280000000808`**: установлен признак доступа только для чтения.

АРФА выбирает свободный номер из переданной маски. При уже подходящих
назначениях устройства сохраняются. Коды ошибок обоих запросов и обоих
дозаказов проходят через общий обработчик.

## Номер тома и BCD

`volume(u)` (**00117**) сдвигает номер устройства на 12 двоичных
разрядов и вызывает **Э50 0105**. Если ответ **больше 9999**,
он возвращается без преобразования: сюда попадают большие идентификаторы
областей. Иначе **00130–00145** выделяют четыре шестнадцатеричные
тетрады BCD и накапливают десятичное значение по правилу
`result := result*10 + digit`.

Умножение машинного целого на 10 развёрнуто обычным генератором
Паскаля: добавление порядка по **74022**, умножение и вызов целой части
по **74136**. Сдвиг сохраняет вытесненную тетраду через РМР.
Это место восстановлено Паскалем с циклом `while`; его команды совпали
с исходным образом.

## Пять загрузочных обменов

После успешного `attach` вызывается **00071**:

| Дескриптор | Откуда | Куда |
|---|---|---|
| 00102 | u42 z002 | лист 1 |
| 00103 | u42 z003 | лист 2 |
| 00104 | u42 z004 | лист 3 |
| 00105 | u42 z005 | лист 4 |
| 00106 | u42 z001 | лист 0 |

Первые четыре обмена выполняются по **00073–00076**. Затем
**00077** переносит команду из **00101** через Э75 в ячейку **6**,
а **00100** переходит на 6. Последний обмен затирает загрузчик
в листе 0. Возврат после Э70 приходится на **7**, вход уже загруженной
программы. Теги команды для трамплина выставляются Э75.

Тела загружаемой системы ДЖИН в самом файле ДЖИП нет: здесь находятся
только поиск областей, подключение и начальный загрузчик.

## Ошибки и проверенное поведение

`fail` получает статус АРФА, добавляет старший признак
**`0x800000000000`** и обращается к **Э50 0202**. М15 указывает на
массив из трёх ALFA-слов, куда эмулятор записывает описание ошибки.
Далее печатаются префикс ` *** ОШИБКА АРХ. = `, три слова текста,
перевод строки и выполняется переход на **76002**.

В изолированном каталоге АРФА первый запрос заканчивается кодом **1**.
Исходная и вновь скомпилированная программы одинаково выводят:

```text
 *** ОШИБКА АРХ. = ТАКОГО ИМЕНИ НЕТ
```

Обе возвращаются в ПУЛЬТ, после `КОНЕЦ` задание завершается нормально.
Полные трассы подтверждают вызов Э63 по **00156**. Реальный запуск
пятизонной системы из исторических областей `РАБОЧ`/`ПРОГР` не проверен:
эти области в тесте отсутствуют. Побайтовое совпадение всех команд
проверено независимо от этой динамической проверки.
