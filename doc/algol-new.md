# NEW и НОВ: интерфейсы Алгола к БАНДИТ

Это две библиотечные группы процедур для работы с базами МАРС-6 через
БАНДИТ. NEW содержит девять объявлений процедур; НОВ — 32, включая
вложенные вспомогательные процедуры. НОВ расширяет интерфейс операциями
над текущей записью, поиском, преобразованием имён и обработкой ошибок.

Исходные тексты извлечены в [new.alg](../algol/new.alg) и
[nov.alg](../algol/nov.alg). Библиотеки на 2148 и 2248 побайтно совпадают.
Ненулевые байты обоих текстов имеют правильную нечётность.

| Группа | Запись каталога | Начало текста | Размер до нулевого слова |
|---|---:|---:|---:|
| NEW | 0747 | 0360.1513 | 557 слов |
| НОВ | 0751 | 0361.0571 | 1135 слов |

Адреса и поля автокода ниже восьмеричные; размеры и индексы в формулах
Алгола десятичные. Константы команд в таблице представлены в hex.

## Подключение и различия

Минимальное подключение:

```text
_БИБ : NEW;
```

Для расширенной группы требуется:

```text
_БИБ : НОВ,UR;
```

Зависимость от UR возникает в `СЛУЧИМЯ(X)`. В каталоге зависимостей НОВ
она отсутствует. Без явного подключения транслятор выдаёт
`НЕ ОПИСАН ИДЕНТИФИКАТОР ’UR’`, даже если СЛУЧИМЯ не вызывается.

В NEW находятся `NEW`, `OPEN`, `СИС`, `ID`, `PUT`, `GET`, `DELETE`, `КТЛ`,
`ИМЯФ`. Операции оформлены как процедуры без результата. Ошибки
обрабатываются общим выходом с печатью сообщения и переходом на 020.

В НОВ процедуры `НОВ`, `NEW`, `OPEN`, `СИС`, `PUT`, `GET`, `DELETE`,
`PUTMOD`, `MOD`, `FINDFIRST`, `FINDLAST`, `FINDNEXT`, `FINDPRED`, `FINDN`,
`GETCUR`, `DELCUR` объявлены булевскими. Есть ERR с таблицей обработчиков.
ИМЯФ возвращает упакованное имя как REAL; ЗИМ помещает его в поле БАНДИТ.

## Вызов системы

Обе группы ожидают БАНДИТ в странице **072000–073777**. Перед вызовом
проверяется слово **072001** на имя `БАНДИТ`. Затем СИС:

1. Сохраняет М4 в служебном слове **072033**.
2. Устанавливает М4 = **072000**, задающий базу системы.
3. Записывает адрес своего обработчика ошибки в **072011**.
4. Устанавливает М16 на метку нормального возврата `Ю2`.
5. Выполняет `ПБ 2(М4)`, то есть переходит на **072002**.

В старой СИС дополнительно копируется имя из 072010 в текст сообщения
об ошибке. НОВ передаёт номер ошибки и адрес сообщения процедуре ERR.

Поля интерфейса, устанавливаемые библиотекой:

| Адрес | Содержимое |
|---:|---|
| 072001 | Сигнатура `БАНДИТ` |
| 072003 | Упакованное слово команд операции |
| 072010 | Шестибайтное имя |
| 072011 | Адрес обработчика ошибки |
| 072013 | Адрес объекта обмена, заданный через ID |
| 072015 | Размер объекта в словах |
| 072016 | OPEN устанавливает адрес буфера 066000 |
| 072017 | OPEN устанавливает адрес таблицы 070000 |
| 072033 | Сохранённый М4 |
| 072037 | Имя текущей записи; NAME возвращает это слово |
| 072040 | Дескриптор размещения создаваемой базы; также буфер в НОВ |
| 072041 | Дополнительное служебное слово создания |

### Фиксированная база BDVECT

Сопоставление с `~/git/leobru/re-mars`, состояние HEAD `364ae10`,
устанавливает **базу блока параметров B = 072000**. В `mars.h`, структура
`bdvect_t`, и в конце `re-mars.b6`, таблица `эквив`, поля имеют следующие
смещения. Их совпадение проверяется независимыми процедурами Алгола:

| Процедура Алгола | Абсолютный адрес | Поле BDVECT | Вычисленная база |
|---|---:|---|---:|
| PUT, GET и другие | 072003 | +003 `orgcmd` | 072000 |
| ИМЯФ / ЗИМ | 072010 | +010 `key` | 072000 |
| СИС | 072011 | +011 `erhndl` | 072000 |
| ID | 072013 | +013 `myloc` | 072000 |
| ID | 072015 | +015 `mylen` | 072000 |
| OPEN | 072016 | +016 `bdbuf` | 072000 |
| OPEN | 072017 | +017 `bdtab` | 072000 |
| СИС | 072033 | +033 `savm4` | 072000 |
| NAME | 072037 | +037 `curkey` | 072000 |

Особенно показательны ID, КТЛ и НОВ. ID передаёт пару адрес/длина именно
через `B+013`/`B+015`. КТЛ после микроопераций LENGTH и DESCR печатает
`B+037` — текущее имя, `B+040` — текст длины, `B+041` — текст даты.
Форматирование этих двух последних слов видно в `re-mars.b6:cmd34`.
НОВ задаёт `myloc = B+040`, используя служебные поля как место для
дескриптора, читаемого из корневого каталога.

Наблюдаемый вызов ожидаемой фиксированной версии можно записать так:

```text
memory[B+003] = microprogram
memory[B+010] = key
memory[B+013] = user_address
memory[B+015] = user_length
memory[B+011] = error_handler
memory[B+033] = saved_M4
M4 = B = 072000
M16 = return_address
jump B+002
```

База BDVECT здесь совпадает с базой БАНДИТ. Заголовок и вход расположены
при B+001 и B+002; некоторые начальные поля общего BDVECT в этой версии
могли иметь специальное назначение. По библиотеке прослежена публичная
часть до B+041. Полный размер и размещение внутренних рабочих полей
фиксированной реализации пока не установлены.

У версии 2048:0657 база кода задаётся М4, а база BDVECT загружается из
слова `B_code+003` в М13. Её внутренние слова, например сохранение М13
при `B_code+013`, отделены от одноимённых смещений пользовательского
BDVECT. Совпадение расположения публичных полей позволяет построить
соответствие интерфейсов; простая замена загрузки М13 на значение М4
привела бы к наложению рабочих ячеек кода на поля блока.

## Операции

В таблице показаны константы, записываемые в 072003. Это полные слова
команд, которые библиотечная группа передаёт ожидаемой версии БАНДИТ.

| Процедура | Слово в hex | Действие интерфейса |
|---|---:|---|
| NEW(НУ,НН,Н,Д,ИМБД) | `00875668D259` | Задаёт размещение и имя создаваемой базы |
| НОВ(ИМБД) | `00000848C259` | Читает дескриптор существующей базы и выполняет INIT; по последовательности команд предназначена для переинициализации |
| OPEN(ИМЯ) | `00001528C259` | Открывает базу; задаёт буфер и таблицу |
| PUT(ИД,ИМЯ) | `000000591349` | Записывает объект под именем |
| GET(ИД,ИМЯ) | `000000012309` | Читает объект по имени |
| DELETE(ИМЯ) | `0000174C0309` | Удаляет запись по имени |
| PUTMOD(ИД,ИМЯ) | `400316440349` | Для существующего имени выполняет UPDATE; для отсутствующего — ALLOC, ADDKEY, затем UPDATE |
| MOD(ИД,ИМЯ) | `000000010309` | Изменяет запись по имени |
| FINDFIRST | `000000000101` | Выбирает первую запись |
| FINDLAST | `000000000002` | Выбирает последнюю запись |
| FINDNEXT | `000000000004` | Выбирает следующую запись |
| FINDPRED | `000000000003` | Выбирает предыдущую запись |
| FINDN(ИМЯ) | `000000000309` | Ищет запись по имени |
| GETCUR(ИД) | `000000000012` | Читает текущую запись |
| DELCUR | `0000000004D7` | Удаляет текущую запись |
| КТЛ, начало | `000000000001` | Начинает перечисление |
| КТЛ, шаг | `00000001C6C4` | Получает и печатает очередную запись |

В НОВ добавлены операции, начиная с PUTMOD. NAME — функция REAL без
вызова системы: читает 072037. КТЛ печатает заголовок `ИМЯ ДЛИНА ДАТА`
и три слова записи при 072037–072041. Окончание перечисления определяется
кодом 020, который перехватывается локально внутри КТЛ.

НОВ(ИМБД) выполняет последовательно OPEN, ЗИМ, устанавливает
072013 = 072040 и вызывает СИС со своим словом команд. Проверки результата
OPEN в этой последовательности нет. Последовательность ROOT, FIND, MATCH,
GET, INIT указывает на переинициализацию базы с уже имеющимся именем:
дескриптор берётся из корневого каталога. Точный перенос полей в INIT
ожидаемой версии и фактическое воздействие на базу требуют проверки.

### Расшифровка микропрограмм по re-mars

Команды упакованы по шесть бит. Первой выполняется младшая шестибитная
группа; следующий код извлекается сдвигом вправо на шесть разрядов.
Это соответствует `Mars::mcprog` в `mars.h` и дешифратору `next` в
`re-mars.b6`.

| Процедура | Порядок исполнения |
|---|---|
| OPEN | ROOT → FIND → MATCH → SETCTL → OPEN |
| GET | FIND → MATCH → GET |
| PUT | FIND → NOMATCH → ALLOC → ADDKEY |
| DELETE | FIND → MATCH → COND → FREE → DELKEY |
| MOD | FIND → MATCH → UPDATE |
| PUTMOD | FIND → NOMATCH → COND → ALLOC → ADDKEY → MATCH → COND → UPDATE |
| FINDFIRST | BEGIN → NEXT |
| КТЛ, шаг | NEXT → LENGTH → DESCR |
| НОВ | ROOT → FIND → MATCH → GET → INIT |
| NEW | ROOT → FIND → NOMATCH → INSERT → ADDKEY → SAVE → INIT |

COND имеет код 00. В re-mars при неуспехе MATCH/NOMATCH следующий COND
разрешает пропустить его и три следующих кода. Поэтому у PUTMOD наличие
имени переводит исполнение сразу к завершающему UPDATE, а отсутствие
проводит через ALLOC и ADDKEY. У DELETE отсутствие имени при этой
семантике пропускает FREE и DELKEY и завершает микропрограмму без удаления.

NEW показывает границы переноса семантики. В re-mars INSERT сохраняет
уже подготовленный дескриптор, а SAVE завершает микропрограмму. В слове
NEW перед INSERT отсутствует ALLOC, а после SAVE стоит INIT. Кроме того,
NEW готовит новые параметры при B+040/B+041, тогда как INIT в re-mars
использует `dbdesc` при B+030. Эти места требуют кода фиксированной
версии для полного объяснения; одной перестановки блока параметров
недостаточно для доказательства работоспособности NEW.

## NEW: параметры размещения

Четыре числовых параметра передаются по имени и преобразуются одним
вспомогательным фрагментом `ПЕР`: режим РА3, прибавление константы
`6400000000000000`, маска **0x7**, восстановление режима РА0.
Поэтому в сохранившемся коде от каждого параметра остаются три младших
разряда. Это относится и к Н, и к Д.

После преобразования формируются поля:

```text
unit = ((НУ & 7) << 3) + (НН & 7)
memory[072040] = ((Д & 7) << 18) + (unit << 12) + (Н & 7)
memory[072041] = (memory[072010] >> 10) << 10
```

Разбиение НУ/НН соответствует двум восьмеричным цифрам устройства.
Ограничение начала и длины тремя разрядами выглядит дефектом этого текста;
создание базы с произвольным диапазоном зон этим кодом не подтверждено.
Расширенная НОВ содержит тот же преобразователь NEW с маской 0x7.

## ID: адрес и размер объекта

ID общая для двух групп. Она проверяет признак в слове описания фактического
параметра (`Р43 = 0x040000000000`). Для скаляра устанавливает длину 1
и берёт адрес из младших 15 разрядов описания. Для массива извлекает
адрес и длину через его дескриптор, в том числе таблицу границ.
Результат помещается в 072013 и 072015.

Таким образом, PUT, GET, PUTMOD, MOD, GETCUR передают системе область памяти
и число слов. Содержимое массива эти оболочки не перекодируют.

## Представление имён

БАНДИТ получает имя в одном слове: шесть восьмибитных кодов ГОСТ,
короткое имя дополняется пробелами. ИМЯФ/ИМЯФ1 поддерживают:

- строковый литерал: убирают внешние кавычки, собирают до шести символов;
- массив числовых кодов: читают элементы 2–7, ожидая в первом элементе
  открывающую кавычку; закрывающая кавычка с числовым кодом 27 начинает
  заполнение пробелами с кодом 15;
- скаляр с уже упакованным именем: используют его 48-битное значение.

В строковой ветви есть специальная очистка байтов со значением 0200.
Точное поведение для всех нестандартных форм строк не проверено.

Старая ИМЯФ сразу пишет имя в 072010. В НОВ ИМЯФ и ИМЯФ1 возвращают
слово; ЗИМ отдельно записывает его в 072010. ПЕЧИМЯФ печатает имя на
терминале с помощью OUTPUT с параметром Щ.

СЛУЧИМЯ(X) получает случайное значение через UR(X) и выбирает из его
разрядов упакованное имя. ИНДЕКСИМ(ИМ,И3,И4,И5,И6) прибавляет положительные
индексы, ограниченные маской 0x3F, к байтам 3–6 имени. Сдвиги равны
24, 16, 8 и 0 бит; исходные байты перед сложением не очищаются.

## Обработка ошибок в НОВ

ERR имеет 17 ячеек OWN REAL для сохранения обработчиков. Один вход
регистрирует обработчик по номеру, другой вызывается при ошибке системы.
Во втором случае используется сохранённое значение:

| Значение | Действие |
|---|---|
| 0 | Стандартная печать ошибки и выход |
| `0x200000000000`, маска К4 | Подавление стандартного выхода |
| `0x000000000010`, константа К20 | Стандартная обработка |
| Описание метки | Переход через служебную процедуру компилятора `*GOTO` |

ON(NОШ,МЕТ) получает описание метки через `*ПАР` и регистрирует его.
IGNOR(NОШ) устанавливает признак подавления, REVISE(NОШ) — значение К20.
После возврата из ERR обработчик СИС явно присваивает результату FALSE.

В исходнике есть незавершённые места булевского интерфейса: на нормальном
возврате из БАНДИТ СИС не содержит присваивания TRUE; DELETE вызывает СИС,
но не присваивает результат DELETE. Эти пути требуют проверки на
совместимой системе. Остальные оболочки обычно присваивают результату
значение СИС, например `PUT:=СИС`.

## Загрузка и версии БАНДИТ

При отсутствии сигнатуры NEW/OPEN выполняют Э70 с встроенным словом обмена:

| Место | Слово обмена | Чтение |
|---|---|---|
| NEW из группы NEW | `0010350000370030` | Устройство 37, зона 030 → страница 35 |
| OPEN в обеих группах | `0010350000370030` | То же |
| NEW из группы НОВ | `0010350000400030` | Устройство 40, зона 030 → страница 35 |

Последнее различие содержится прямо в автокоде: у NEW из НОВ записано
`СЧ3500,УИ030`, в остальных местах — `СЧ3500,РА030`.
При текущем подключении 2068 устройство 40, зона 030 содержит КТЛБД.
Поэтому такая автозагрузка NEW из НОВ подставляет каталог в место системы.

В обычном `pult2068.b6` устройство 37 не подключено. Вызов OPEN из группы
NEW доходит до Э70 в **04121**, получает слово `0010350000370030`
и завершается **АВОСТ 42**.

Для отдельной проверки устройство 37 было подключено как
`37(2068-1777)` с `--725`: зона 030 становится зоной 027 частной копии
2068. Так библиотека получает сохранившийся БАНДИТ в ожидаемую страницу
35. Сигнатура проходит, затем СИС записывает своё слово команд в 072003
и переходит на 072002. В данном образе это место не содержит нужного
входного перехода: исполнение попадает в поле 072003 и завершается
**АВОСТ 31 при 072004**. Подключением тома совместимость не достигается.

Команда BD работает с отдельным интерфейсом и загружает БАНДИТ при
074000; её проверки описаны в [bd.md](bd.md). Доказательство совместимости
вызовов NEW/НОВ с этим образом отсутствует.

### БАНДИТ на томе 2048, зона 0657

В 2048:0657 находится ещё одна версия с сигнатурой БАНДИТ и рабочим
входом при 072002:

```text
072002  СЧИ М16; ПБ 0125(М4)
072125  ЗП 7(М4); СЧИ М13
072126  ЗП 013(М4); СЧРЖ 07777
072127  ЗП 041(М4); РЖА 3
072130  СЧ 3(М4); УИ М13
```

Для загрузки её библиотечным OPEN в отдельном задании достаточно
`лент 37(2048-627)` с `--725`: обращение к зоне 030 устройства 37 читает
2048:0657. В проверках использовались частные копии дисков.

Эта версия использует **отдельный блок параметров**: слово 072003 задаёт
его базу, которая загружается в М13. Затем система обращается к полям
через М13, например 072133 читает по указателю из `017(М13)`, а 072142
получает слово команд из `3(М13)`.

У извлечённых NEW/НОВ слово команд помещается непосредственно в 072003.
В трассе OPEN записывает туда `0000002512141131`, и команда при 072130
устанавливает **М13 = 041131**. Таким образом, система принимает младшие
разряды команды за адрес блока. В этом месте требуется согласование
интерфейса.

Простой вызов OPEN с последующим OUTPUT 123 завершился без АВОСТ и
вывел 123. Трасса показывает, что чтения каталога при этом не произошло.
Дополнительные проверки:

| Проверка с 2048:0657 | Результат |
|---|---|
| OPEN, затем КТЛ | Задача завершилась через Э62 на 00400; последующий OUTPUT не исполнен |
| OPEN и FINDFIRST через НОВ с проверкой результатов | Тайм-аут; зафиксирован некорректный дескриптор Э70 на 072140 |
| OPEN, NEW, PUT, GET через группу NEW | АВОСТ 24 при 014107; обратное чтение значения не подтверждено |

Следовательно, возвращение из одиночного OPEN устанавливает лишь наличие
исполняемого входа. Работу баз данных через эти NEW/НОВ на версии
2048:0657 ещё предстоит проверить после согласования блока параметров.

## Выполненные проверки

Запуски выполнялись последовательно на частных копиях дисков.
Совместный пример преобразования имён и регистрации обработчиков сохранён
в [tests/algol-new.alg](../tests/algol-new.alg). Он выводит АВС, АВ0,
АВС, АБ0 и 123. При вводе через `сис алг` после заключительного `_end`
добавляется пробел, затем файл завершается `//` и ETX.

| Проверка | Результат |
|---|---|
| `_БИБ : NEW;` и OUTPUT 123 | Компиляция и исполнение успешны |
| `_БИБ : НОВ;` | Не описан UR |
| `_БИБ : НОВ,UR;` и OUTPUT 123 | Компиляция и исполнение успешны |
| ПЕЧИМЯФ для литералов ABC и AB0 | Выведены АВС и АВ0 |
| ИМЯФ литерала → скаляр → ПЕЧИМЯФ | Имя сохранено |
| Массив кодов `[26,32,33,0,27,…]` → ПЕЧИМЯФ | Выведено АБ0 |
| ON(1,L), IGNOR(2), REVISE(1), затем OUTPUT 123 | Регистрация завершена, программа продолжила исполнение |
| OPEN со штатным подключением | АВОСТ 42 при загрузке с устройства 37 |
| OPEN с образом БАНДИТ через устройство 37 | Сигнатура распознана, несовместимый вход, АВОСТ 31 |

Работа обработчиков при реальной ошибке БАНДИТ, результаты булевских
операций и запись/изменение базы не проверены.
