# Паскаль-исходники ЧИСТКИ и ЭХОЛОТА

[ЧИСТКА](../pascal/chistka.pas) и
[ЭХОЛОТ](../pascal/echolot.pas) записаны в диалекте
`~/git/besm6/pasauto-re/pretty.pas`: подчёркнутые ключевые слова,
`_(`/`_)`, первые шесть значимых символов имён, SETUP/ROLLUP, BIND
и небольшие CODE-вставки для обращений к АДСИС.

**Это не побитово воспроизводящие исходники.** Уровень восстановления
двух программ различается:

- **ЧИСТКА** получена из адресной декомпиляции образа 10.12.82.
  Сохранены процедуры, вложенные функции и порядок обхода списков.
  Переходы через условные блоки заменены структурными IF с обратным
  условием; ненужные метки удалены. Восстановлены ветви THEN/ELSE
  с общей точкой продолжения и альтернативы после досрочного EXIT.
  Процедуры имеют мнемонические имена; комментарии при определениях
  и оставшиеся числовые метки сохраняют исходные восьмеричные адреса.
  [Таблица имён](chistka-names.md) связывает процедуры с адресами.
  Описаны шестисловные
  записи имён и шестнадцатисловные записи блоков. Восстановлены явные
  операции с аккумулятором, строки, упаковка имён и управление памятью.
- **ЭХОЛОТ** восстановлен по образу 24.10.86. Лексический анализ,
  описания типов, параметры, блоки, FORWARD, цепочки вызовов и форматирование
  отчёта используют исходные структуры. Входы и размеры всех 42 процедур,
  главной программы и служебного хвоста совпадают. Остаются различия
  входов АДСИС и использования М10 при чтении нескольких масок.

Массив литералов ЧИСТКИ **00011–00546 совпадает пословно** с оригиналом:
350 слов, начало кода 00547. Раздел `const` задаёт исходный порядок
скалярных и упакованных ALFA-констант 00014–00074. Значения 00075–00236
создаются из описаний типов и использований в программе в нужном порядке; их явные
объявления удалены без изменения массива. Константа дескриптора
InputReadZone (00505) объявлена в BindInput (04744). Строки WRITE/BIND создают остальные слова
по мере компиляции процедур. Повторные вхождения строк сохранены:
компилятор записывает их заново, тогда как одинаковые скалярные
константы объединяет. Односимвольный вывод отделён от строкового,
а две ветви завершения запроса используют общий участок с сообщением.
31 текстовая константа префикса объявлена строками с мнемоническими
именами: `Spaces`, `KwBegin`, `KwFunction`, `OpSCh` и другие. Их имена
используются вместо 48 соответствующих литералов в теле программы.
`Spaces` содержит шесть пробелов ГОСТ: `0F0F0F0F0F0F`.
Скрипт пересборки проверяет весь массив литералов отдельно от кода.
Размеры и адреса входа **всех 43 процедур совпадают** с дисковым образом.
Главная программа занимает 0121 слово с адреса 05122; служебный хвост
компилятора начинается с 05243, общая граница — 05262. Эти границы также
совпадают. Числа здесь восьмеричные.

[tests/chistka-layout.py](../tests/chistka-layout.py) распознаёт прологи
по результату статического дизассемблирования и сравнивает каждый участок
между соседними входами отдельно. Пересборка завершается ошибкой при
расхождении размера или адреса входа любой процедуры либо главной программы.
Полная таблица находится в `comparison.json`, поле `routine_layout`.

В ScanBody (02733) и TypeDeclarations (03644) замыкающие переходы записаны через CODE с символическими
метками и явным концом машинного слова. Это сохраняет исходную упаковку:
следующий возврат начинается с левой половины отдельного слова.

Побитового совпадения пока нет: в проверенном образе различаются 140 слов —
дата и адреса входов АДСИС. Совпадение
размеров проверяется отдельно от полного сравнения слов.

## Проверка

```sh
make checkanalyzers DISPAK=/home/leob/git/dispak/build/dispak/dispak
```

[tests/rebuild-analyzers.py](../tests/rebuild-analyzers.py):

1. Создаёт временные копии томов и исходный архив.
2. Подключает целый майский компилятор Паскаль 9 (17.05.88) из
   2248:01101–01114 к частному 2068.
3. Компилирует каждый исходник и сохраняет машинный образ.
4. Сравнивает все слова выделенных зон с оригиналом, включая заголовок
   и остаток последней зоны. Сгенерированные слова не исправляются.
5. Устанавливает образ с командными тегами в частный том и запускает
   проверочные тексты: **20 случаев ЧИСТКИ и 24 случая ЭХОЛОТА**.
6. Проверяет сохранность исходных томов и входных массивов.

По умолчанию различия двоичных образов записываются в отчёт.
Строгая проверка включает отказ при любом несовпадении:

```sh
python3 tests/rebuild-analyzers.py --exact --dispak /path/to/dispak
```

С текущими исходниками эта строгая проверка завершается ошибкой.
Граница программы в слове 00005 при майской компиляции:

| Программа | Дисковый образ | Реконструкция |
|---|---|---|
| ЧИСТКА | 05262 | 05262 |
| ЭХОЛОТ | 07646 | 07646 |

В каждом `build/<name>-rebuild/` находятся `compile.input`,
`compile.out`, `compile.trace`, `original.bin`, `generated.bin` и
`comparison.json`. Отчёт содержит хеш исходника, хеши обоих образов,
границы программ и полный список различающихся адресов.
Календарная дата при компиляции не подменяется.

Логи функциональных проверок лежат в `build/chistka-rebuilt-check/`
и `build/echolot-rebuilt-check/`. Проверки адресов входа исходного образа
при этом отключаются; проверки результатов и дисковых обменов сохраняются.

Для отдельного прогона уже собранного образа:

```sh
python3 tests/chistka.py --image build/chistka-rebuild/generated.bin --dispak /path/to/dispak
python3 tests/echolot.py --image build/echolot-rebuild/generated.bin --dispak /path/to/dispak
```

## Что остаётся для точного восстановления

Для ЧИСТКИ остаётся устранить различия адресов входов АДСИС и даты.
Размеры всех процедур, главной программы и массива
литералов уже совпадают; полное сравнение слов по-прежнему выявляет различия.

Детали дисковых программ и исходные адреса описаны в
[чистке](chistka.md) и [эхолоте](echolot.md).

Все числа таблицы восьмеричные. Совпадают размеры, входы, адреса
литералов, локальные и глобальные смещения и цели внутренних переходов.
Регистры и операции сверяются строго; четыре использования М10 для масок
и изменения CASE декабрьского компилятора перечисляются отдельно.
Сохранён переход 01013 в непосредственно следующее слово 01014:
в исходнике ему соответствует явный GOTO после установки флага С.

[tests/echolot-layout.py](../tests/echolot-layout.py) распознаёт все 42
пролога исходного образа, включая вложенные процедуры, и записывает их
размеры в `routine_layout.original_procedures` файла `comparison.json`.
В пересборке также 42 процедуры. Для каждого различающегося полуслова
сохраняются исходный и новый адреса и поля команд. Различие
короткого и длинного форматов учитывается. Чтение с нулевым регистром после
МОДА/МОД использует C: его операнд проверяется как неизменное смещение поля.
Такие команды исключаются из проверки значений литералов, даже когда
смещение численно попадает внутрь массива литералов.

Массив литералов проверяется отдельно и строго, без перемещения адресов:
все 336 слов 00011–00530 совпадают побитово. Общий префикс CONST задаёт
00014–00057. Текстовые константы этого префикса записаны строками в ГОСТ
(режим A1, установленный по умолчанию). Псевдокомментарий `(*=a0*)` переключает
строковые и символьные константы в ИТМ; `(*=a1*)` возвращает ГОСТ.
Например, `(*=a0*) ItmName='PROCED'; (*=a1*) GostName='PROCED';`
даёт слова `8D8A838E9092` и `30472E31253F` соответственно. Преобразование
проверено майским и декабрьским компиляторами. В текущем префиксе нужны
ГОСТ-значения ключевых слов и мнемоник.

Значения 00060–00064 возникают в нужном порядке при
обычных употреблениях; отдельные объявления для них избыточны. Удаление
объявления для 00057 (24 в восьмеричной записи) меняет порядок литералов
начиная с 00057. Локальный CONST ReadCodeBounds задаёт 00175–00217; маски и
образцы команд записаны как 48-битные слова, чтобы границы множеств не
создавали дополнительных скаляров. ParseType заранее объявляет литералы
00440 и 00441. Строки отчёта создаются в исходном порядке непосредственно
в analyze; повторные WRITE-строки сохраняют отдельные слова.

Проверка `literal_pool` в `build/echolot-rebuild/comparison.json` должна
иметь `exact_match: true` и пустой список различий. Файлы
`original-literals.txt` и `generated-literals.txt` в той же папке содержат
адрес, двенадцать шестнадцатеричных цифр и представление ГОСТ каждого слова;
их можно сравнить через tkdiff. Любое изменение массива или адресов ссылок
из восстановленных процедур останавливает пересборку с ошибкой. Параметр
`--compile-only` выполняет компиляцию и сравнение без функциональных проб.

ReadRequest сохраняет четыре локальные переменные, общую ветвь выхода,
встроенную справку, пропуск трёх начальных `=`, разделители параметров,
счётчик ошибок и подключение массивов через INPUT и файловый объект F.
Проверки `request-options`, `missing-length`, `retry-limit` выполнены
на оригинале и пересборке: соответственно `===` и `Т,С`, отсутствие
длины, семь ошибок с подсказкой после третьей и автоматическим выходом.

ReadCodeBounds читает F последовательно. FindReturn ищет переход к 74012
или 74007 в любой половине слова, сохраняет адрес и потребляет это слово.
IsPrologue различает вызов общего пролога и встроенную последовательность
установки кадра. При неудаче уже просмотренные слова остаются потреблёнными.
Счётчик codepos на единицу больше адреса текущего F@; начальное значение
014 соответствует слову 013. На первом вызове запоминается первый пролог,
на следующих — границы очередной процедуры. Результаты возвращаются через
MAPIA как ALFA, что соответствует вызовам 74050 в оригинале.

PrintField (01177) разворачивает ALFA в массив с границами 0..12, заменяет
ведущие нулевые байты пробелами и проверяет наличие букв. Имена выводятся
в шесть колонок, числовые поля — в пять; полностью нулевое поле сохраняет
последний ноль. Адаптер octal использует эту процедуру для ширины 5.
TrimName (01256) сдвигает содержимое ALFA до первого ненулевого байта,
дополняя справа пробелами; применяется при сверке имени машинного образа.
AddAddress (01302) выполняет MAPAI, сложение и MAPIA. SkipThrough (01314)
потребляет заданный разделитель и считает промежуточные концы строк;
признак конца строки хранится в изменяемой переменной, исходное значение 0175.
Последние две процедуры сохранены для дальнейшего восстановления их вызовов.
Все четыре вложены в основной анализатор с исходным лексическим уровнем 3.

Проверка code-frames компилирует функцию INNER с параметром VAR внутри OUTER.
Оригинальный ЭХОЛОТ выполняет ветвь 01132 распознавателя встроенного пролога;
оригинал и реконструкция выдают INNER 00053:0014 и OUTER 00067:0014,
глубину процедур 015 и общую сумму 030 (с кодом 0161). Этот пример проверяет
и отсутствие ложной рекурсии при присваивании результата INNER:=V.

Diagnostic (01332) выводит номер ошибки, строку, имя и класс найденной
записи, текущий символ, класс токена и упакованное имя. Перечисления классов
дают исходные таблицы TYPE/CONST/VAR/PROC/FIELD/TAGF/TAGV и
ОГ/ИД/ПС/ЦЕ/AL/RE/СН/CF. Конструкторы 01401–01467 восстановлены с исходной
вложенностью уровня 4. NewIdentifier создаёт запись до поля 8 включительно,
связывает её с корзиной хеш-таблицы и возвращает указатель. NewConstant
устанавливает класс CONST, тип и значение. NewBuiltin выделяет шесть слов,
ставит класс PROC, тип результата и очередной номер встроенной процедуры.
Хеш равен MAPAI от имени после побитового пересечения с '000177'
(маска 0203407); результат имеет семь значащих разрядов.

InitHistorical (01470) выполняется перед анализом исходного текста.
Трасса проверочного запуска nested подтверждает вход в неё и в NewIdentifier,
NewConstant, NewBuiltin; список записывается в executed_initializers отчёта
пересборки. Diagnostic выполняется в проверке scanner-error: она сверяет номер,
строку и поля состояния. Ошибки оставшейся модели синтаксического разбора
по-прежнему выводит отдельная error.

Инициализация очищает две хеш-таблицы по 128 элементов и рабочие поля,
заполняет таблицы возвратов и входов АДСИС, устанавливает конец строки 0175.
Пул литералов объявлен на 3120 слов; слово 9 содержит NIL, слова 10 и 11 —
0 и 1, текущий индекс равен 11. Максимальное число ошибок равно 10.
Создаются BOOLEAN, INTEGER, CHAR, безымянный SET, REAL, ALFA и УКNIL;
затем FALSE, TRUE, TEXT, INPUT и OUTPUT. У TEXT размер 30 слов и ширина
символа 8 разрядов; у INPUT/OUTPUT адреса упакованы как ALFA '000007' и
'000010'. Значение TRUE хранит упакованный адрес литерала '000013'.
Следом регистрируются 32 процедуры и 24 функции с исходными типами результата.
Поля с именами sNNNNN обозначены по восьмеричному смещению от М1.
Глобальный кадр размещён по исходным обращениям к памяти:

| Смещение от М1 (восьмеричное) | Поля |
|---|---|
| 00012–00142 | режимы, лексер, счётчики, указатели типов и сохранённый HEAP |
| 00143–00206 | returnOps[3..8,1..6] |
| 00207–00227 | extraOps[1..17] |
| 00230–00427 | namehash[0..127] |
| 00430–00627 | oldhash[0..127] |
| 00630–01011 | рабочие записи WITH: withTable[0..17] и withLast |
| 01012–01015 | savedChars[1..4] |
| 01016–07075 | literalPool[1..3120]; literalPool[9] находится в 01026 |
| 07076–07077 | цепочки s07076 и pairHead |
| 07100–07244 | рабочая область savedNames[0..100] |
| 07245–07251 | три рабочих поля, heapReserve и errors |
| 07252–07416 | calls.top и calls.names[1..100] |
| 07417–11444 | файл F: 22 служебных слова и буфер 1024 слова |

Объявление F использует `(*=b4*)`: четыре блока по 256 слов.
Конец глобального кадра равен 11445; этот адрес участвует в TypeCheck.
Граница WITH записана как 18 элементов и отдельная последняя запись,
чтобы объявление сохраняло исходный порядок появления числовых литералов.
Состав неиспользуемых рабочих областей требует дальнейшего уточнения.
В 07100–07244 находится savedNames — 101 слово ALFA для имён EXTERN
в ИТМ. После F дополнительные глобальные переменные не выделяются.

AddExponent (02015) объединяет исходное слово с маской
6400000000000000C. PutLiteral (02027) ищет poolValue в пуле с индекса 9,
возвращает найденный индекс через MAPIA или добавляет слово. FORCE отключает
поиск; достижение индекса 3120 вызывает Diagnostic(23). Сохранены исходные
границы слов и переход из машинного цикла поиска в ветвь найденного слова.
AddExponent пока проверяется статически. PutLiteral вызывается при
чтении длинных строк восстановленным сканером; выполнение подтверждено трассой.

Проверка компоновки дополнительно сравнивает неизменяемые локальные
смещения, непосредственные размеры выделения/ширины и значения читаемых
литералов. Она сохраняет различающиеся адреса в comparison.json.
Проверка выявила границы 0..12 у массивов PrintField и TrimName; поле 0
не обрабатывается, но определяет размещение остальных локальных переменных.
Адреса переходов, таблиц переходов и вызовов внутри восстановленного
участка сверяются с учётом его переноса. Для локальных кадров проверяются
смещения вплоть до уровня 5; чтения литералов через М10 также проверяются.
Для всех 957 обращений через М1 в 42 восстановленных процедурах строго
сравниваются исходные операнды, включая смещения индексируемых массивов,
МОДА/МОД и адрес конца кадра. Все эти операнды совпадают. Адреса входов
АДСИС остаются в отчёте различий.

ScanToken 02463 восстановлен целиком. Его кадр содержит
исходные 43 локальных слова: массив символов 0..12, индексы, два указателя,
флаг, два REAL, ALFA, массив 20 символов и два целых поля.

Digraph (02066) сохраняет первый символ, читает следующий и при совпадении
с заданным вторым символом заменяет пару одним кодом. OctalEscape (02131)
читает три восьмеричные цифры, ограничивает первую значением 3 и записывает
полученный байт обратно в INPUT@. ScanError (02102) вызывает Diagnostic;
сохранён также присутствующий в образе код восстановления для ошибок 0..4.
Diagnostic уходит в основной цикл через 07560, поэтому эти ветви после него
в текущем образе не выполняются.

ReadIdentifier (02156) читает буквы диапазона А..Z и цифры 0..9.
В упакованном имени остаются первые шесть символов; остальные потребляются.
Короткие имена дополняются слева нулевыми байтами ГОСТ.

OptionComment (02276) после '(' потребляет '*', разбирает блок параметров
при следующем '=' и затем вызывает SkipComment. Три его помощника имеют
лексический уровень 5. SkipComment (02206) поддерживает вложенные (*…*),
закрывает комментарий по *), считает строки и сбрасывает счётчик токенов

ReadSwitch (02260) принимает '+' либо '-'.

| F, G, S, V, D | один флаг s00014 |
| L, Д, Л, О, Ч | один флаг s00111 |
| Р, Т, С | флаги s00105, s00106, s00076 |
| R, М, Х, I | флаги s00107, s00110, s00116, s00113 |

Все числа пределов этой таблицы десятичные. Имена букв приведены в ГОСТ:
например, Latin L и кириллическая Л имеют разные коды. Ошибка значения
передаётся ScanError(13). После закрытия комментария предусмотрен переход
в начало тела сканера 02465.

ScanToken ищет имена в четырёх режимах: текущий уровень, все уровни,
поля активных WITH и поля заданного типа записи. После имени или константы
восстанавливается обычный режим поиска. Неизвестные имена сохраняются
в diagWord; указатель найденной записи передаётся в diagIdent.

Числа допускают суффиксы В/С/Т, десятичную дробь и показатель Е.
Т-форма собирает восьмеричные цифры с другого конца машинного слова.
Перед очередным десятичным умножением проверяется граница 10^12;
модуль десятичного показателя ограничен 18;
масштаб вычисляется возведением 10 в степень через последовательное
возведение в квадрат. Деление показателя записано как trunc(precision/2):
это воспроизводит исходную последовательность преобразований и деления.

Короткая строка помещается в ALFA; удвоенная кавычка и ≡ooo дают один
символ. Длинная строка хранится шестисимвольными словами в пуле литералов,
с принудительным добавлением через PutLiteral. PoolWord (03316) выполняет
MAPAI индекса, возвращает слово пула и обрабатывает нулевой индекс отдельно.

ScanToken непосредственно используется в ParseType, FormalParams,
analyze и ScanBody; классы токенов и указатели на имена не преобразуются.


Проверочные тексты scanner и scanner-lines выполнены на оригинале и
пересборке. Они проверяют именованные границы массива, вложенные комментарии,
вещественное число с показателем, суффиксы В/С/Т, короткие и длинные строки,
удвоенную кавычку, вставку ≡101 и параметры N!,А1,С+.
scanner-error проверяет ошибочную вставку ≡400: ERROR=2, NL=2,
NAME=WRITEL, CLASS=PROC, C=(, VSCT=AL, ЯП=WRITEL; итоговый отчёт не выводится.
Пересборка проверяет исполнение сканера, его помощников, PutLiteral,
PoolWord, ScanError и Diagnostic по адресам из таблицы восстановления.

TypeCheck (03346) проверяет совместимость описателей типов. При выключенном
параметре С и при совпадении указателей результат истинен. Иначе должны
совпадать формы типов. Для скалярных типов отдельно допускается пара
ALFA/CHAR; у диапазонов сравниваются обе границы и базовый тип. У массивов
рекурсивно сравниваются тип элемента и индексный тип, у файлов — тип элемента
и параметр упаковки. Множества совместимы по форме. Различные записи дают
ложь; форма kAlias вызывает Diagnostic(2).

Для указателей nilType совместим с любым указательным типом. Остальные
указатели сравниваются через типы объектов. Chain (03327) добавляет пару этих
типов в трёхсловную связную запись и вызывает TypeCheck. Повторная пара в
любом порядке завершает рекурсию с успехом. Первый спуск сохраняет границу
кучи через SETUP; после сравнения сбрасывает список и восстанавливает кучу
через ROLLUP. Это позволяет сравнивать циклические определения.

ScalarConstant (03520) возвращает тип и индекс литерала в ALFA. Она принимает
NIL, скалярные именованные константы, целые, вещественные, строки и символы.
Знак разрешён отдельным параметром; после рекурсивного чтения минус меняет
целое или вещественное значение и повторяет помещение в пул. Именованная
константа должна иметь класс CONST и пустую связь data. При заданном
ожидаемом типе вызывается TypeCheck; ошибка возвращает NIL в указателе типа.
NilOffset содержит упакованный индекс '000011', соответствующий исходному
литералу NIL в позиции 9 пула.

BitWidth (03671) возвращает ширину поддерживаемого упакованного типа.
Размер объекта должен быть равен одному слову. Для диапазона нижняя граница
должна быть неотрицательной, верхняя — меньше 48; результат вычисляется
через ВН как 49 минус номер старшей единицы. Для указателя ширина равна 15,
для BOOLEAN — 1, для CHAR — 8. Остальные случаи возвращают 0.

Fields (03735) строит девятисловные описатели полей записи и записывает их
в отдельную хеш-таблицу oldhash. Имена одной группы сначала связываются
через слово 5; после разбора типа в слово 6 помещается указатель типа,
в слово 8 — смещение поля. Слово 7 содержит владельца записи. Селектор
CASE имеет класс TAGF; именованный селектор занимает одно слово записи,
безымянный — ни одного. Для каждого значения создаётся семисловный TAGV;
значение хранится в слове 1, цепочка значений — в слове 5. Список сортируется
по убыванию упакованных индексов литералов и проверяется на повторы. Ветки
разбираются рекурсивно; размер записи становится максимумом размеров веток.
Слово 6 каждой TAGV получает полный размер соответствующей ветки.

ParseType (04354) разбирает перечисления, диапазоны, указатели, записи,
массивы, файлы и множества. Ограничение 1 запрещает файловый тип,
ограничение 2 допускает только скалярный тип или диапазон. Именованный
синоним получает форму kAlias. Перечисления связывают восьмисловные
описатели констант через слово 7. Многомерный массив представлен цепочкой
описателей; размеры вычисляются от последнего измерения к первому,
в слове 8 хранится индекс литерала шага либо нулевое слово для шага 1.
Размер файла равен 22 словам плюс trunc(48/ширина) при поддерживаемой
упаковке с шириной от 1 до 24; без упаковки — 22 слова.

Неизвестный тип в определении указателя допускается флагом allowForward;
создаётся предварительный описатель и увеличивается pendingTypes. Это
отдельные поля исходного кадра 00074 и 00064: флаг опции Е в 00104 и
переменная 00054 имеют другое назначение.

[tests/echolot-types.py](../tests/echolot-types.py) строит отдельный образ с
восстановленными процедурами и
[проверочным драйвером](../tests/echolot/type-driver.pas), который заменяет
тело основного анализатора. Текст
[types.pas](../tests/echolot/types.pas) проверяет массив, обычную и вариантную
запись, упакованные файлы CHAR, 0..7, 0..48 и указателей, множество,
предварительный тип указателя, отрицательную целую константу, символ,
_NIL, TRUE и вещественную константу. Дополнительно проверяются циклические
указательные типы, освобождение временной цепочки сравнения, ALFA/CHAR,
выключение контроля совместимости и совпадающие/различающиеся границы.
Группа формальных параметров `(A,B:integer; VAR C:ARRAY[1..2] OF integer;
FUNCTION FN:real; PROCED PR)` проверяет пять имён и смещения 3, 4, 5, 6, 7
с конечным курсором 010. Всего 21 успешная проверка. Три дополнительные
пробы проверяют отказ для массива по значению и функции с результатом-массивом
(ERROR=4), повторного имени параметра (ERROR=2). Трасса подтверждает
исполнение BitWidth, Fields, ParseType, ScalarConstant, TypeCheck, Chain

FormalParams (05245) разбирает группы параметров по значению, VAR,
FUNCTION и PROCED. Слово 7 описателя владельца указывает на первый параметр,
слово 10 считает имена. Параметры связаны через data (слово 3); последний
ссылается обратно на владельца. По значению допускается только однословный
тип; VAR передаёт одно слово адреса, в том числе для массива. Результат
формальной функции ограничен формами kSc, kRng, kPtr и kSet. Для PROCED
указатель типа результата равен NIL.

Значение получает восьмисловный описатель CONST, ссылка — семисловный VAR,
функция или процедура — девятнадцатисловный PROC. Тип передаётся в слове 5,
текущий адрес — в слове 6 для значений и VAR либо в слове 8 для процедурных
параметров. После каждого имени AddAddress увеличивает адрес на одно слово.
В отличие от полного компилятора, здесь флаг traced параметру не присваивается.

SkipParameters (05454), вложенная в ProgramHeader, читает токены до первой
закрывающей скобки, затем читает ещё один токен. Имена файлов и параметры
привязки здесь не проверяются; ProgramHeader проверяет точку с запятой.

ProgramHeader (05465) создаёт девятнадцатисловный описатель главной программы.
При выключенном параметре С в пул заранее заносятся целые 0..47, начиная
с индекса 10, и устанавливается указатель конца пула. Заголовок должен
содержать PROGRAM и имя класса ИД. Процедура печатает имя и обнуляет
поля размеров и признаков анализа в описателе.

Если указан массив машинного кода, F первоначально находится на слове 0.
Первый GET переводит его на имя в слове 1; несовпадение с TrimName имени
текста даёт «НЕ ТЕ КОДЫ !» и возврат к запросу. Четыре GET переводят F
на слово 5, откуда берётся граница кода; ещё шесть оставляют F на слове 013.
Это положение используется ReadCodeBounds при дальнейшем последовательном
чтении.

В описатель заносятся служебные слова 0x2024 и '0000СА', пустой список
параметров и нулевое число параметров. Курсор кадра '000012' вместе с
описателем передаётся рекурсивному вызову analyze. После анализа требуется
точка. Разность максимального и собственного размеров вычисляется до
добавления служебных расходов. Признаки 00015/00016 добавляют три слова
к обоим размерам, признак 00015 — дополнительно 128. Итог учитывает резерв
NEW; при подключённом коде выводятся также его размер и сумма памяти с кодом.
Все числовые поля проходят MAPIA и PrintField.

Внешний вызов analyze с начальным словом '00000 ' выполняет инициализацию
и ProgramHeader. Рекурсивный вызов разбирает блок в исходном кадре и
передаёт его собственный и максимальный размеры в описатель подпрограммы. Конечный отчёт печатает
ProgramHeader; завершение «КОНЕЦ» находится в главной программе.

Для вывода ProgramHeader сохранены исходные смещения локального кадра analyze:
013 — глобальные переменные, 014 — процедуры, 016 — сумма, 062 — сумма с кодом,
063 — код. Счётчик циклов находится в 020, счётчик InitHistorical — в 021.
В 061 хранится начало списка вызываемых имён текущего блока. Область
022..060 содержит рабочие поля анализа блока;
весь исходный кадр содержит 49 локальных слов.

Числовые результаты выводятся через MAPIA, имена — через PrintField.
Списки вызываемых имён занимают срезы общего массива calls.names.

Проба [header.pas](../tests/echolot/header.pas) содержит список INPUT, OUTPUT,

проверяют чтение заголовка машинного образа и отказ при другом имени.
Пересборка проверяет входы в ProgramHeader и SkipParameters по трассе.

RememberCall (05725) проверяет имена в срезе listBegin..calls.top−1.
При совпадении возвращается; новое имя помещается в calls.names[calls.top],

массив имён следует за ним. Локальный listBegin находится в 061 кадра analyze.

Перед сканированием тела analyze сохраняет calls.top в listBegin.
После отчёта счётчик возвращается к началу этого среза.

программы. Повторный вызов печатает повторную строку; уникальность списка
RememberCall относится к списку имён режима С. Вывод Т выполняется в ScanBody.

Проба [calls-slices.pas](../tests/echolot/calls-slices.pas) содержит LEAF,

ScanBody (05743–06113) восстановлен и подключён к основному анализатору.
Кадр содержит два INTEGER и ALFA. Цикл читает токены через ScanToken;
BEGIN, CASE и SELECT вызывают ScanBody рекурсивно, END завершает вызов.
Для процедур нулевого уровня учитываются специальные имена CODE и NEW:
CODE пропускается до закрывающей скобки, NEW увеличивает newcnt.
Для пользовательских процедур сохраняется уникальный список вызовов и
обновляется максимум суммы собственного кадра и глубины вызываемой процедуры.
Самообращение функции отличается от присваивания её результату по токену
128. Рекурсия отмечается в proc16; после обхода блока его собственный кадр
прибавляется к глубине ещё раз. Переход через FORWARD даёт предупреждение.
Поля proc13 и proc15 имеют тип BOOLEAN: машинные проверки читают их напрямую.

ScanBody изменяет поле глубины исходного identifier. В analyze
после него учитывается proc16, как в 07347–07352 образа.

[body.pas](../tests/echolot/body.pas) проверяет вложенные BEGIN и CASE,
пропуск CODE и повторные вызовы LEAF. Оригинал и пересборка дают WALK:
ЛОК=3, ВХОД=3, СУМ=6, один LEAF в списке; общая сумма равна 020.
Трасса подтверждает рекурсивное выполнение ScanBody и ветвь CODE в 06105.
Основные пробы и отдельный драйвер типов выполняются при пересборке.

У ScanBody совпадают размер, команды, локальные и глобальные смещения,
переходы и адреса литералов. Общий пролог в 05743 совпадает; в 06064 отличается адрес реализации MAPIA. Пул 00011–00530 совпадает полностью.
PruneHash (06114–06136) перебирает все 128 голов переданной хеш-таблицы.
Пока голова отлична от NIL и её адрес не меньше scopeMark, она заменяется
ссылкой next. Первый более ранний узел сохраняется вместе с остатком цепочки.
scopeMark находится в слове 051 кадра М2; функция использует также исходные
слоты 020 для индекса и 006 для текущей головы. Параметр — таблица по ссылке;
в оригинале функция вызывается для namehash и oldhash при выходе из блока.
Все команды PruneHash, включая адрес общего пролога, совпадают. Функция исполняется в основных пробах при смене таблиц имён.

Проверка HASH отдельного драйвера сохраняет узел, созданный до границы,
удаляет две последующие головы, включая узел ровно на границе, и проверяет
пустые цепочки. Проверяются обе таблицы и крайние индексы 0 и 127.
Трасса драйвера подтверждает выполнение PruneHash.

### Основной анализатор, 06137–07541

`analyze` занимает исходные 01403 слова и начинается в 06137. Все его
вложенные процедуры расположены перед телом в исходном порядке.
Главная программа начинается в 07542 и занимает 0036 слов; служебный
хвост — 07600–07645, конец сохраняемого образа — 07646. Литералы,
начала и размеры всех 42 процедур, главной программы и хвоста совпадают.

Начальный вызов с diagWord='00000 ' выполняет InitHistorical и
ProgramHeader. ProgramHeader вызывает analyze рекурсивно для корневого
блока. Каждый блок разбирает LABEL, CONST, TYPE, VAR, вложенные процедуры
и функции, затем требует BEGIN и передаёт тело ScanBody. Пользовательские
имена находятся в исторических namehash и oldhash. Все описатели имеют
исходный формат identifier; отдельного структурного разборщика нет.

Сохранён кадр из 49 локальных слов. В 06144 читается режим вывода СБОЙ
из 76013 в savedOutput, слот 023. Младший бит задаёт wasTerm в слоте 032.
В отчёте этот признак определяет число имён в строке: с кодом 2/8,
без кода 4/10 для терминала и печати соответственно. Отступы — 0100 и
060 символов. reportIndex в слоте 022 также используется при выводе
четырёх младших восьмеричных цифр длины кода.

Инициализация блока сохраняет следующие значения:

| Смещение в М2 | Поле | Значение |
|---|---|---|
| 017 | frameNext | ALFA следующего свободного локального адреса из параметра |
| 027 | l00027 | 0, назначение не установлено |
| 030 | savedCheck | текущий s00076, режим C |
| 051 | scopeMark | граница кучи для удаления локальных хеш-ссылок |
| 052 | savedForward | исходная голова forwardType |
| 054 | currentLabel | текущая запись метки |
| 055 | savedLabels | исходная голова s07076 |
| 056 | l00056 | NIL, назначение не установлено |
| 061 | listBegin | начало списка вызываемых имён блока |
| 064 | l00064 | 0, назначение не установлено |

Устанавливаются allowForward=true, pendingTypes=0 и s00044=1.
Токен после заголовка должен иметь класс ПС, иначе Diagnostic(1).
[block-token.pas](../tests/echolot/block-token.pas) проверяет число вместо
такого токена: оригинал и пересборка дают ERROR=1, NL=2 без итога хранения.

### LABEL, 06173–06231

Каждый целочисленный номер метки добавляется в начало цепочки s07076.
Запись занимает шесть слов:

| Смещение | Поле | Значение при объявлении |
|---|---|---|
| 0 | value | номер из builtinNo |
| 1 | state1 | 0 |
| 2 | level | codeLevel |
| 3 | state3 | 0 |
| 4 | next | предыдущая голова s07076 |
| 5 | state5 | 0 |

Назначение трёх рабочих полей пока не установлено. Поля записываются
в исходном порядке 0, 2, 3, 1, 5, 4, затем обновляется голова цепочки.
NEW вызывает исторический вектор AL 74025. Разделители — `,` и `;`.
Нецелочисленный номер даёт Diagnostic(24), неверный разделитель —
Diagnostic(25); после списка снова требуется ПС, иначе Diagnostic(1).

[labels.pas](../tests/echolot/labels.pas) объявляет 10 и 20 на разных
строках с комментарием. Трассы проверяют размер выделения, каждое поле и
цепочку 20 → 10 → NIL. Четыре отказа проверяют имя вместо номера,
двоеточие вместо разделителя, пустой элемент после запятой и число после `;`.

### CONST, 06232–06417

Блок CONST включён непосредственно в analyze. Он занимает 0166 слов.
После CONST требуется имя, ещё не объявленное на текущем уровне.
Для него выделяются восемь слов: имя, уровень, хеш-ссылка, NIL в DATA,
класс CONST, тип INTEGER и место для значения со служебной ссылкой.
Описание включается в namehash до чтения правой части. ScalarConstant
устанавливает фактический тип и помещает в constvalue адрес литерала
в виде ALFA. PoolWord читает значение, PutLiteral размещает результат
операции и обновляет адрес.

| Смещение в М2 | Поле | Назначение |
|---|---|---|
| 005 | p | тип прочитанного значения |
| 006 | t | объявляемая константа |
| 053 | rightConst | временный восьмисловный описатель правого операнда |
| 057 | binaryOp | 0 либо номер операции 1–4 |
| 060 | leftValue | целое значение левого операнда |

Правая часть — скалярная константа с необязательным знаком, затем одна
необязательная операция `+`, `-`, `*` или `/` и второй скалярный операнд.
Знак непосредственно перед вторым операндом запрещён. Операция требует
intType у обоих операндов. Скобки и цепочки операций здесь не разбираются.
Множитель обозначается `*` (ГОСТ 031); `×` (ГОСТ 024) даёт ошибку разделителя.

Для умножения сохранён вектор ЦУ 74060; деление переводит операнды в REAL
через 74024 и вызывает TRUNC через 74057. Проверены `30/4 = 7` и
`-19/4 = -5`. Эти вызовы записаны в CODE. Недостижимая ветвь CASE с номером
0 сохранена вместе с переходом к диагностике.

| Ошибка | Проверка |
|---|---|
| 2 | требуется имя либо оно уже объявлено на текущем уровне |
| 3 | требуется `=` |
| 4 | неверный первый операнд |
| 5 | требуется `;` после значения или единственной операции |
| 6 | неверный второй операнд, разные или нецелые типы, деление на ноль |

[Драйвер CONST](../tests/echolot-constants.py) извлекает этот блок из
рабочего исходника. Он проверяет 13 целых значений, типы REAL, BOOLEAN,
CHAR, ALFA, NIL и десять отказов. Литералы префикса 00011–00507 драйвера
сверяются с оригиналом; полный массив 00011–00530 проверяется у рабочего
образа. Отдельный драйвер сохраняет смещения кадра и пересчитывает адреса
вызовов восстановленных процедур и внутренних ветвей. Все 0166 слов
совпадают для майского компилятора; декабрьский меняет пять регистров
М0 → М10 в таблице CASE. Результаты — `constants-layout.json` и
`constants_probe` в общем отчёте. [const-block.pas](../tests/echolot/const-block.pas)
проверяет CONST в составе полной программы: массив имеет длину 20,
глобальный кадр и сумма равны 036.

### TYPE, VAR и вложенные подпрограммы

TYPE (06420–06520) вызывает ParseType с именем и номером хеш-ячейки.
Отложенное указательное имя можно завершить объявлением `имя=↑тип`;
счётчик pendingTypes уменьшается. При выходе из TYPE отключается
allowForward и проверяется отсутствие незавершённых типов (ошибка 33).
[type-forward.pas](../tests/echolot/type-forward.pas) проверяет завершение
NODE=↑R и последующее использование LINK; глобальный кадр равен 013.

VAR (06521–06726) создаёт цепочку семисловных описателей группы имён,
разбирает общий тип и назначает последовательные адреса через AddAddress.
Файловая ветвь учитывает размер элемента, буфер и внешние привязки через
пятисловную запись filebinding. Внешняя привязка хранит имя, два числовых
параметра, признак использования и ссылку на следующую запись. Эта ветвь
сохранена по коду; отдельной динамической проверки внешних привязок нет.

PROCEDURE/FUNCTION (06727–07271) создаёт 19-словный описатель, вызывает
FormalParams, сохраняет курсор кучи и рекурсивно вызывает analyze.
Собственный кадр начинается с 3 слов у процедуры и 4 у функции.
Поле proc14 — BOOLEAN; proc11 связывает незавершённые FORWARD, proc12
сохраняет курсор кучи. После выхода восстанавливается уровень и курсор,
PruneHash очищает namehash и oldhash. У завершённого FORWARD отдельно
удаляются хеш-ссылки на параметры.

Форма завершения FORWARD — `PROCEDURE P+`, затем сразу декларации или
BEGIN тела. Повторение обычного заголовка даёт ошибку 22, незавершённая
цепочка FORWARD перед BEGIN — ошибку 23.
[forward.pas](../tests/echolot/forward.pas) проверяет P с параметром,
вызов из Q до определения P, предупреждение FORWARD, затем P+.
Кадр P равен 004, Q — 003, итог — 015. Уже вычисленная глубина Q
после определения P не пересчитывается.

В 07272–07352 устанавливается размер кадра и резерв NEW, затем ScanBody
обходит тело. Резерв корня вычисляется до этого обхода, что сохраняет
пропуск NEW, встречающегося только в главной программе. proc16 отмечает
рекурсию; собственный кадр добавляется к максимальной глубине повторно.
В 07353–07535 печатаются размеры, границы кода и срез вызываемых имён.
В 07536–07541 размер возвращается через paramName, calls.top восстанавливается.

### Сверка полного образа и компиляторы

```
python3 tests/rebuild-analyzers.py --program echolot --compiler may \
  --dispak /home/leob/git/dispak/build/dispak/dispak
python3 tests/rebuild-analyzers.py --program echolot --compiler december \
  --dispak /home/leob/git/dispak/build/dispak/dispak
```

Используется майский компилятор 17.05.88 из 2248:1101–1114 либо декабрьский
09.12.88 из 2148 с двумя проверяемыми исправлениями из tools/volume2068.json.
В отчёте записываются версия, SHA-256 компилятора и исходника. Томы копируются
для запусков и проверяются на неизменность. Каталоги результатов —
`build/echolot-rebuild` и `build/echolot-rebuild-december`.

Параметр K12 задаёт исходные 030000 слов кучи. Главная программа сначала
читает запрос, затем восстанавливает курсор кучи, очищает s00117 и вызывает
analyze. Это сохраняет исходные границы главной программы и служебного хвоста.

| Проверка | Май | Декабрь |
|---|---|---|
| Вход analyze, размер | 06137, 01403 | 06137, 01403 |
| Главная программа | 07542–07577 | 07542–07577 |
| Служебный хвост, конец образа | 07600, 07646 | 07600, 07646 |
| Литералы 00011–00530 | точное совпадение | точное совпадение |
| Входы и размеры 42 процедур | совпадают | совпадают |
| Различающихся слов с оригиналом из 4096 | 181 | 231 |
| Основные пробы | 39 пройдены | 39 пройдены |
| Драйвер типов | 22 проверки, 3 отказа | 22 проверки, 3 отказа |
| Драйвер CONST | 18 значений/типов, 10 отказов | 18 значений/типов, 10 отказов |

`routine_layout` проверяет все процедуры, главную программу и хвост.
`code_comparison` сравнивает обе полукоманды каждого слова 00531–07645,
включая операнды и служебный код. Входы АДСИС сравниваются через реальные
векторы 74000–74077 из исходного образа АДСИС, дизассемблируемые тем же
инструментом. Допускается только замена перехода через такой вектор
на его точную цель. Все остальные различия останавливают пересборку.

Помимо входов АДСИС, майский код различается в четырёх полукомандах:
06145:1, 07445:0, 07445:1, 07446:0. Оригинал использует М10 при чтении
литералов, пересборка — М0. Адреса и значения масок совпадают. Это три
машинных слова; полного побитового совпадения кода нет. Проверка режима
вывода и узлов LABEL дополнительно использует трассы.

Декабрьская пересборка меняет ещё 50 слов таблиц CASE с М0 на М10:
ScanError — 5, ScanToken — 4, TypeCheck — 8, ScalarConstant — 8,
ParseType — 8, FormalParams — 4, analyze — 13 (CONST — 5, тип результата
функции — 8). Других различий между двумя пересборками нет.
`compiler_literal_base_differences`, `compiler_case_base_differences` и
`may_comparison` сохраняют эти замены явно. В полном сравнении 4096 слов отдельно учитывается дата в слове 00002.
Остаток зон после 07646 совпадает. Для мая 181 различающееся слово — это
177 переходов через векторы АДСИС, три слова с М10/М0 и дата; для декабря
добавляются 50 слов CASE.
