# СПИС: чтение, просмотр и редактирование текстов

СПИС — двухзонный ассемблерный редактор текстового буфера ПУЛЬТа.
Первая зона обслуживает **С**: чтение массива из архива, просмотр строк,
выдачу на АЦПУ и перфоратор. Вторая обслуживает **Р** и поиск по образцам,
доступный также через С. Обе зоны работают совместно в листах 0 и 1.
Изменения остаются в ОЗУ; для сохранения массива служит приказ **З**.

Исходные зоны — **01045–01046** томов 2148/2248, в 2068 — **045–046**.
Шестибайтные образы 2148 и 2248 совпадают целиком; SHA-256 двух зон:
`1e364cfa193ce5c9406c33cd03974f29c23e1a231b4fbdf1f9ccd963b84c2f43`.

Адреса, номера зон, устройств и коды символов далее восьмеричные.
Номера строк в приказах, размеры в словах/байтах и номера томов —
десятичные. Отдельные значения слов и маски приведены в hex.

## Листинг и проверки

```sh
make spis
python3 tests/spis.py --dispak=/home/leob/git/dispak/build/dispak/dispak
```

Листинг `build/СПИС.lst` объединяет обе зоны по адресам **00000–03777**;
`build/СПИС.dump` содержит полный дамп исходных зон.
Разметка — [syms/СПИС.sym](../syms/СПИС.sym).

Проверка запускает сеансы последовательно на временных копиях 2068/2248,
с отдельным HOME и архивом 2345. Основной буфер заранее содержит короткий
текст ГОСТ. Вывод и полные трассы сохраняются в `build/spis-check/`.
Проверяются результаты редактирования, чтение архива и прохождение ветвей
АЦПУ/перфоратора. Физическая печать и качество перфокарт этим тестом
не проверяются. После серии сверяются хеши исходных файлов томов.

Описание синтаксиса находится в [§ 10 руководства](PULT-User.md#pdf-019)
и [§ 11](PULT-User.md#pdf-021). Руководство употребляет также длинные
названия СПИС и РЕД. В таблицах исследуемого монитора этим двум входам
соответствуют **С** и **Р**. Приказ `РЕД NAME` выбирает Pascal-программу
НОВРЕД через БАВТ.

## Загрузка и возврат

| Приказ | НАБЛ | Обмен | Вход |
|---|---|---|---|
| С | 56312 | u40 z045 → лист 0 | 00010 → 00023 |
| Р | 56314 | u40 z046 → лист 1 | 02010 |
| С с образцом | 00130 | u40 z046 → лист 1 | 02017 |

**02010** загружает первую зону в лист 0 по дескриптору
**02005 = `0010000000400045`**. **02011–02013** сверяют слово **00020**
с сигнатурой **02006**, соответствующей `э70 11; зп`, и при несовпадении
повторяют загрузку. Поэтому Р располагает всеми общими процедурами
первой зоны независимо от предыдущей команды.

Входы сохраняют состояние НАБЛ:

| Откуда | Куда | Назначение |
|---|---|---|
| 57773 | 00012 | признак режима работы с памятью |
| 57767 | 00013 | текущая система кодировки |
| 57760 | 01277 | номер терминала |

**00020–00022** возвращают НАБЛ с барабана 27:037 в лист 27,
восстанавливают текущую систему в **57767** и переходят на **56010**.
Ветви вывода и редактора могут также непосредственно передать управление
этому входу НАБЛ. Pascal runtime АДСИС в работе СПИС не участвует.

## Буфер и номера строк

Основной текст начинается с **010000**. Для АЛГ просмотр и редактор
начинают содержимое с **010002**, пропуская два служебных слова.
Текст упакован по шесть байтов в машинное слово, старший байт первым.

| Область / слово | Использование |
|---|---|
| 00662 | индекс кодировки: 0 АЛГ, 1 АВТ, 2 ЛИСП, 3 КОД, 4 БЕМ |
| 00663 / 00666 | адрес и маска следующего входного байта для С |
| 00664 / 00667 | адрес и маска выходного байта |
| 00665 | текущий номер строки |
| 00701 / 00702 | начало и конец диапазона строк |
| 00732 / 00733 | конец строки и конец текста для С |
| 03541–03560 | первый образец поиска |
| 03561–03600 | второй образец поиска |
| 03700… | текст замены; при вводе с терминала может быть длиннее |
| 04000… | буфер выдачи |
| 06000… | собираемый редактором новый текст |
| 010000… | основной текст |

Маска байта **00765**, также **03145**, равна **`0xff0000000000`**.
Последовательные сдвиги на восемь бит выбирают байты слева направо.
С читает их через **01003**, записывает через **01033**.
Редактор использует **03151** и **03200**, с входным указателем в М6,
выходным в М7 и отдельными масками **03106 / 03105**.

Номера строк хранятся как десятичные цифры в отдельных байтах.
Например, номер 123 имеет внутреннее значение **`0x000000010203`**.
**01073–01107** принимают до пяти цифр, сдвигая накопленное слово
на восемь бит перед добавлением следующей цифры. **01051–01072**
увеличивают номер с десятичным переносом; **01111** формирует печатный
номер с ведущими пробелами и точкой.
Максимум **00756 = `0x000909090909`** означает 99999.
Проверка `С 10:12` выдаёт строки 10, 11 и 12.

## Кодировки и признаки конца

**00156–00171**, а для Р **02017–02024**, находят текущую систему
**57767** в таблице **00707–00713**. Неизвестная система приводит
к сообщению `СИС !` и выходу.

Ниже приведены исходные значения таблиц; ФОРМ может их переопределить.
Код указан для байта, расположенного в старших разрядах слова.

| Система | Конец строки, 00715+k / 03125+k | Конец текста для С, 00725+k | Пара конца, 00771+k и 00776+k |
|---|---|---|---|
| АЛГ | 0174 | 0172 | 0127, 011 |
| АВТ | 046 | 0140 | 063, 0140 |
| ЛИСП | 022 | 0140 | 063, 0140 |
| КОД | 0175 | 0172 | 0172, 0175 |
| БЕМ | 0115 | 0172 | 0172, 0175 |

При чтении АЛГ **01027–01031** снимают бит чётности. При вводе
литерала редактор устанавливает нечётность в **03420–03424**;
для АВТ/ЛИСП действует табличная перекодировка **03425–03437**.
Ветка ЛИСП дополнительно учитывает вложенность скобок и ограниченную
длину строки: **01142 / 01160**, **03353–03370**.

**00172–00205** читают параметры ФОРМ из НАБЛ **57753–57757**:
переопределяют ограничитель строки, пару конца, интервал вывода
и счётчик продолжения. Р также применяет **57757** к таблице
концов строк (**02025–02027**).

Распознаватель **01013–01015** сравнивает предыдущий и текущий байт
с парой **00753 / 00754**. Редактор делает аналогичную проверку
в **03173–03176**. Для КОД существенна именно пара **0172,0175**.
В проверочном тексте с единственным 0172 просмотр успевал напечатать
четыре строки, после чего сканирование продолжалось за концом массива;
редактирование также не завершалось в установленный срок.
Тестовый текст заканчивается парой 0172,0175.

## С: чтение и выдача

**00026–00126** разбирают имя, скобки, диапазон строк и режим выдачи.
Имя сохраняется в **00672**. Отсутствие имени устанавливает **00737**:
работа продолжается с текстом, уже находящимся в памяти.
Двоеточие задаёт диапазон; без правой границы используется предельный
номер. Буква **А** включает АЦПУ, **П** — АЦПУ и перфорацию.

```text
С ТЕСТ             чтение массива из текущего архива
С 1:4              выдача четырёх строк текущего буфера
С 3                одна строка
С 3:               выдача от строки 3 с продолжением
С () А             весь текст на АЦПУ
С 1:4 П            строки 1–4 на перфоратор
С 9999             достижение конца массива и выдача его номера
С БУФ              первые четыре зоны буфера на МБ
```

С без диапазона после имени загружает массив и возвращается к НАБЛ.
Обработчики печати выбираются таблицей **00216–00222**. ГОСТ проходит
через **00304–00370**, АЛГ/АВТ — через **00223–00256**, ЛИСП —
через **00257–00275**. Общая выдача — **00372**:

- **00407**: Э64 **00437**, формат для ИТМ;
- **00411**: Э64 **00435**, формат для ГОСТ;
- **00413**: местный терминальный форматтер, входы **01317 / 01321**.

Форматтер первой зоны использует резидентный вывод **76005**
в **01454**. Его таблицы **01503–01543**, преобразования ИТМ/ГОСТ
**01563–01626** и рабочая строка **01627–01642** находятся в самой зоне.
Режим П включает оба признака — **00744** и **00110**: сначала
формируется печатная выдача, затем перфокарта.

### Архив и БУФ

Локальный загрузчик **01204** принимает параметры по **01205–01207**:
шифр архива, имя, начальный адрес ОЗУ. Он использует текущий каталог
на барабане 27:036, запасную копию по дескриптору НАБЛ **57776**
и пары имени/расположения в **06001…**, с границей каталога **06377**.

**01223–01233** сверяют шифр каталога с **01205**; при необходимости
перечитывают каталог с МЛ и обновляют барабанную копию.
**01234–01243** ищут имя и формируют ошибку при отсутствии.
**01244–01261** извлекают начало и длину из каталожного слова
и читают зоны последовательными Э70 с увеличением номера зоны
и номера листа ОЗУ. В проверке `С ТЕСТ` прочитал u50 z0101 в лист 4
и передал текст последующему `С 1:4`.

Имя **БУФ** распознаётся отдельно в **01212–01220**. **01214** читает
барабан 27, зоны **0–3**, в листы **4–7**. Дескриптор увеличивается
на **01267 = `0x000040000001`**; возвращаемая длина — четыре зоны.
Это совпадает с ограничением С БУФ в руководстве. Приказ **СБУФ**
с отдельной длиной относится к другому обработчику.

### Перфорация

**00445–00577** преобразуют выдаваемую строку в битовое представление
карты. Для АВТ/ЛИСП применяются таблицы **00620–00661**;
**00555–00560** подсчитывают единичные разряды и добавляют нечётность.
Собранные карты занимают область **06000–07730** с шагом **030** слов.
**00574** отправляет заполненную порцию, **00302** — последнюю
неполную порцию через Э71 **00600**. Дескриптор
**`0010603010000000`** означает операцию перфоратора.
В проверке четырёх коротких строк достигнут **00302**.

## Поиск через С и окно контекста

```text
С 1 'ААА'
С 1 'БББ':'ГГГ'
```

**00127–00131** устанавливают признак **00741**, загружают вторую зону
и переходят на **02017**. Общий разбор сохраняет образцы по
**03541 / 03561**. **02551–02577** доводят сканер до заданной строки,
ищут первый образец и, если задан, второй. Основная процедура
сопоставления — **03215–03325**.

Она сохраняет позицию сканера, маску байта и номер строки
(**03116–03122**). При частичном несовпадении восстанавливает позицию
и начинает сопоставление со следующего символа. Выбор продолжения
осуществляется через **02717–02735**; значения М12 задают отдельные
продолжения поиска, копирования, замены и выдачи. Это позволяет одним
байтовым процедурам обслуживать обе команды.

Номер найденной строки формируется через **01111**. Контекст имеет
границы машинных слов: **02570** отступает на два слова от сохранённого
указателя, **02573** без второго образца добавляет к нему три слова.
Получается окно из шести слов, то есть 36 байтов.
При двух образцах правую границу определяет второй поиск
(**02601–02603**). **02605–02623** копируют окно в буфер **04000**
и передают общей выдаче.

Граница **010000** здесь не проверяется. При поиске ААА в самом начале
проверочного буфера читаются также нулевые **07776–07777**:
терминал печатает `1. 000000000000ААА`, затем остальной попавший
в окно текст. Код ГОСТ 0 изображает цифру 0. Это следствие выбранного
окна контекста; строковый номер при этом найден правильно.

При расстоянии между границами свыше **02670 = 20** слов
**02624–02640** печатают начало и конец контекста отдельно.
Пустой первый образец приводит к **02653–02656**:
«НЕПРАВИЛЬНО ЗАДАН ОБРАЗЕЦ». При отсутствии совпадения выдается
«НЕ НАЙДЕН ОБРАЗЕЦ», с образцом из приказа; сообщение формируется
через **03006–03043**, шаблон по **03064**. Оба случая проверены.
Точная выдача контекста при стандартной АЛГ-кодировке здесь
динамически не проверена.

## Р: операции и алгоритм перестройки

| Приказ | Действие |
|---|---|
| `Р 2='НОВАЯ'` | заменить строку 2 |
| `Р 2:3='НОВАЯ'` | заменить диапазон одной строкой |
| `Р 2` | удалить строку 2 |
| `Р 2:3` | удалить диапазон |
| `Р 2=(4)` | заменить строку 2 копией строки 4 |
| `Р 0,'НОВАЯ_175'` | вставить самостоятельную строку перед первой, в КОД |
| `Р 3 'ААА'='Х'` | заменить первое вхождение образца начиная со строки 3 |
| `Р 1:4 'ААА'='ХХ'Ц` | повторять замену в заданном диапазоне |
| `Р 2=Т` | принять заключённый в кавычки текст следующей посылкой |

Разбор **02036–02224** заполняет номера строк, два образца, текст
замены и признаки операции. Пустая замена означает удаление.
Скобки справа от `=` включают копирование диапазона исходного текста
в область замены (**02441–02510**). Двоеточие позволяет пропустить
правую границу диапазона.

**02225–02240** начинают проход: М6 = **010000**, М7 = **06000**,
для АЛГ соответственно **010002 / 06002**. **03334** доходит до
нужной строки с копированием или пропуском символов, в зависимости
от М2. При поиске внутри строки действует **03215**.

**02265–02301** вставляют замену, пропускают заменяемый фрагмент
и копируют оставшийся хвост. Текст замены подаёт **03520**.
**02302–02307** ставят граничное слово **00670**, затем копируют
собранный текст из области **06000…** в **010000…** с постоянным
смещением **02000** слов. Копирование идёт **от конца к началу**,
по убыванию М7, до **06000** включительно. В **02305** к индексу
М1 = −06000 прибавляется М7; нулевой результат завершает перенос.
Так сохраняется текст при перекрытии исходной и конечной областей.
Исходная часть текста, нужная для копирования строк, сохраняется
до этой стадии.

**03053–03056** вызывают просмотр изменённой позиции через первую
зону. После удаления печатается строка, занявшая место удалённой.
При отсутствии требуемой строки **02772–02774** формируют сообщение
«НЕТ СТРОКИ N = …». В проверке `Р 20='Х'` сохранил исходные четыре
строки и выдал эту диагностику.

Ц устанавливает **02177**. **02511–02550** переводят одиночное
сопоставление в цикл замен с сохранением границы диапазона;
для открытой границы подставляется 99999. На исходном тексте

```text
1. ААА
2. БББ
3. ААА ВВВ
4. ГГГ
```

`Р 1:4 'ААА'='ХХ'Ц` даёт:

```text
1. ХХ
2. БББ
3. ХХ ВВВ
4. ГГГ
```

### Литералы, вставка и терминальный ввод

**03374–03447** читают текст в кавычках. Две последовательные
закрывающие кавычки означают один символ внутри текста:
проверка `Р 2='Э050''105'` дала `Э050’105`.
Для АЛГ добавляется нечётность, для ИТМ применяется перекодировка.
Остаток незаполненного буфера помечается единичными байтами.

Вставка с запятой соединяет фрагменты без автоматического создания
новой строки. Проверка `Р 0,'НОВАЯ'` дала первую строку `НОВАЯААА`.
`Р 0,'НОВАЯ_175'` дала самостоятельную строку НОВАЯ, сдвинув прежнюю
первую строку на вторую. Настройка разделителей имеет значение:
[руководство](PULT-User.md#pdf-021) требует для АЛГ ставить конец
строки в начале вставки, для остальных систем — в конце.

Режим `=Т` по **02201** переключает входной буфер НАБЛ на **06000**,
открывает дополнительную посылку через **57037** и принимает литерал
через ту же процедуру **03374**. В проверке

```text
Р 2=Т
'НОВАЯ'
С 1:4
```

вторая строка заменена, остальные сохранены. Разбор параметров
и выдача `=Т` используют процедуры НАБЛ; основной проход замены
остаётся внутри СПИС.

## Границы исследования

Динамически проверены 18 случаев: просмотр, десятичный диапазон,
замена строки, удаление, копирование, вставка конца строки, замена
по образцу, Ц, ввод `=Т`, кавычка в литерале, ошибка номера строки,
поиск с окном контекста, отсутствие совпадений, пустой образец,
чтение архива, С БУФ, АЦПУ и перфоратор.
Проверки выполнены на перенесённом СПИС тома 2068.

Табличные ветви АЛГ/АВТ/ЛИСП/БЕМ, длинный двухобразцовый контекст,
разбиение выдачи на продолжения и многостраничный текст замены
описаны по коду; отдельные динамические проверки этих режимов
не выполнены. Не установлено назначение каждого слова остающегося
содержимого образа вне рабочих процедур и таблиц.
