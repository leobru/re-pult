# ДАЙ: служебный монитор ПУЛЬТ

ДАЙ занимает **одну зону 01005** системных томов 2148 и 2248 и исполняется
в **00000–01777**, лист 0. На томе 2068 это зона **005**. БАВТ по имени
`дай` читает её в **66706** и передаёт управление в **00007**. АДСИС для
этого не загружается: ДАЙ написан на ассемблере, пользуется НАБЛ и СБОЙ,
вызывает подпрограммы через индексные регистры и изменяет свои команды.

Монитор объединяет копирование зон и памяти, обслуживание устройств,
создание архивов, сравнение файлов, формирование пакетной задачи и запуск
Дубнинского монитора с перехватом экстракодов. Таблица действительно
содержит **15 подкоманд**. Это конкретная версия ДАЙ; перечень приказов
в историческом руководстве шире и местами описывает другой интерфейс.

Адреса, номера устройств, зон, коды и числовые параметры ниже восьмеричные,
если явно не указано иное. Количества слов, байтов и символов в пояснениях
десятичные. Адреса ФОРТ приведены также для его копии в листе 36.

## Исходный образ и листинг

```sh
make dai
```

Создаются `build/ДАЙ.lst` и `build/ДАЙ.dump`, без запуска dispak.
Разметка находится в [syms/ДАЙ.sym](../syms/ДАЙ.sym). Дамп сохраняет все
1024 слова зоны, в том числе данные и остаточный код. Тип **257** запрещает
анализ исполнения в областях данных; тип **520** задаёт базу М10:
056000 в командах ДАЙ, 0 в отдельном входе перекодировки.

Шестибайтные образы 2148 и 2248 **полностью совпадают**, SHA-256:

```text
9eb05b230794a44bd05b067d5be69ce4051d3a7f6a3f38cf9f6e622dfe9e3c40
```

## Диспетчер и параметры

**00007** устанавливает М16 = **76002**, резидентный выход СБОЙ.
Правая половина этого слова — `0x3A3A3A`, сигнатура `ЫЫЫ`, которую
БАВТ узнаёт как машинную программу. При исполнении она одновременно
выполняет `уиа 35072(М3)`; рабочие вызовы затем устанавливают М3 заново.

**00010** уменьшает М17 на единицу. После этого:

| Поле | Содержимое |
|---|---|
| `0(М17)` | `ДАЙ` |
| `1(М17)` | Подкоманда |
| `2(М17)…` | Значения её аргументов |
| `М14` | Таблица типизированных ссылок сканера СБОЙ |
| `М10` | База НАБЛ, **056000** |

Сканер описан в [разборе СБОЙ](sboy.md). По умолчанию числа восьмеричные;
суффикс `Д` позволяет явно задать десятичное число. Имена сравниваются
как шестибайтные слова ГОСТ с пробелами справа.

**00011–00014** перебирают пары `(имя, пб обработчик)` в **00016–00053**.
Совпадение ведёт на слово перехода; **00054 = 0377** завершает таблицу.
При отсутствии имени выполняется **00015**: печать `НЕ ДАМ` из 00055
через 76005, затем возврат по М16.

| Подкоманда | Имя в таблице | Обработчик |
|---|---|---|
| ЛЕНЛЕН | 00016 | 00527 |
| ПАУЗУ | 00020 | 00061 |
| НАПНАП | 00022 | 00507 |
| ВРЕШ | 00024 | 00077 |
| ПАМПАМ | 00026 | 00713 |
| НОВАРХ | 00030 | 01065 |
| ЛЕНТ | 00032 | 00404 |
| ШИФР | 00034 | 00477 |
| ДЕШ | 00036 | 00327 |
| СРАВН | 00040 | 00776 |
| АЦПУ | 00042 | 01053 |
| КТЛБИБ | 00044 | 00754 |
| РАЗР | 00046 | 00104 |
| ФОРТ | 00050 | 01225 |
| КОДГО | 00052 | 00070 |

Обычные завершения: **00575** печатает `НЕТ`, **00702** — `ЕСТЬ`,
оба уходят через **76002**. Несколько обработчиков возвращаются прямо
в **56010**, то есть `пб 10(М10)`. Все аргументы в целом не проверяются:
в частности, отсутствие обязательного числа не обязательно означает ноль.
Подкоманды без параметров нельзя использовать как безопасную проверку
операций копирования.

## НАПНАП: копирование зон

```text
дай напнап U1 Z1 U2 Z2 N [NOPR]
```

**00507** обнуляет 00110, выбирая исполнение в текущем задании.
**00510–00515** записывают число зон в 00135 и строят дескрипторы:

```text
00272 = 0010010000000000 | (U1 << 12) | Z1
00273 = 0000010000000000 | (U2 << 12) | Z2
```

Здесь `<< 12` означает сдвиг на 12 двоичных разрядов. Начальный буфер —
лист 1. В **00516–00517** командами Э75 изменяются **00262–00263**:
вместо пакетного завершения ставятся печать `ЕСТЬ` и выход в ПУЛЬТ.

Без `NOPR` выводится запрос вида `1 ЗОН С 50 . 0 НА 51 . 0`.
**00572–00574** требуют точного ответа **`О.К.`**; другой ответ даёт `НЕТ`.
Слово **00302 = 0x452E30470F0F** — именно четырёхбуквенное `NOPR`
с двумя пробелами. Написание `NOPRIN` из примера руководства не равно
этой константе.

**00232–00243** читают порцию зон в последовательные листы памяти,
**00244–00251** записывают её на приёмник. Константа **00143** увеличивает
сразу номер листа и зоны. После порции **00253–00256** оставляют текущие
номера зон, но возвращают поле листа в обоих дескрипторах к 1.

Порция содержит **17 зон**, листы **01–021**, а не 16: индекс 00145
начинается с нуля и сравнивается с **020** после очередного чтения.
Запись также выполняется для индексов от 020 до 0 включительно.
Проверка переноса **022 зон** подтвердила порядок: 17 чтений, 17 записей,
затем одно чтение и одна запись. Все 1024 слова каждой из 18 зон,
включая теги, совпали с источником.

Нулевой счётчик и перекрывающиеся диапазоны на одном устройстве не имеют
специальной обработки. Это перенос порциями, без гарантий `memmove`
для дисковых областей.

## ЛЕНЛЕН: сформировать пакетную задачу

```text
дай ленлен МЛ2345 Z1 МЛ2399 Z2 N [NOPR]
```

Здесь аргументы — **имена томов вида МЛdddd**, а не номера направлений.
**00601–00605** проверяют два старших байта `МЛ` и выделяют четыре
младших байта. **00527–00553** подставляют в паспорт **00110–00134**
шифр текущего задания, тома и параметры копирования. Исходные направления
пакета — **57** и **30**; если имена томов одинаковы, второй ЛЕНТ исключается,
а оба обмена используют направление 57.

После такого же подтверждения, как у НАПНАП, **00677–00701** вызывают
**Э50 7701** с адресом 00110. Ответ сравнивается только с **077777**:
это значение даёт `НЕТ`, остальные — `ЕСТЬ`.

Пакет содержит машинный код: заголовок **00206–00212**, вход **00213**,
установка шести команд **00264–00271** в **04000–04005**, подготовка
дескрипторов в **00223–00227** и общий цикл копирования **00230–00263**.
Сообщения **00150–00205** записаны в ИТМ; паспорт — в ГОСТ.
**00275–00276** содержат `ЕКОНЕЦ` и коды завершения.

В проверенном dispak пакет **не принят**: разбор паспорта сообщает
`Unknown passport entry: ПРИО 0`. При этом ДАЙ всё равно печатает `ЕСТЬ`:
проверка только на 077777 не обнаруживает эту ошибку Э50 7701.
Следовательно, ответ ДАЙ здесь не доказывает ни постановку задания,
ни копирование томов. Исполнение сформированного пакета не подтверждено.

## ПАМПАМ: копирование памяти

```text
дай пампам A1 A2 N [NOPR]
```

Это перенос **N слов оперативной памяти** с A1 на A2. Без `NOPR`
**00714–00727** печатают запрос и проверяют `О.К.`. М17, который
портит процедура вывода, сохраняется в 00011 и восстанавливается.

**00730–00736** устанавливают М1 = A1 + N, М2 = A2 + N и М3 = 1 − N.
При N = 0 сразу печатается `ЕСТЬ`. **00737** сравнивает начала областей:

- A1 < A2: **00741–00743** копируют от конца к началу, уменьшая М1 и М2.
- A1 ≥ A2: **00744–00746** проходят от начала к концу, используя М3
  как отрицательное смещение относительно концов областей.

Циклы выполняют ровно N переносов. Запись идёт через **Э75**, а не
обычную ЗП; для машинного кода это существенно из-за контроля команд.

Проверены перенос восьми слов из 00016 в 04000, сдвиг семи слов
04000 → 04001 и обратный 04001 → 04000. Трасса подтверждает правильные
значения и направление обхода при обоих вариантах перекрытия.

## НОВАРХ и КТЛБИБ

### Создать пустой архив

```text
дай новарх U Z NAME
арх NAME,U,Z
```

**01065–01071** проверяют U < **070**, Z < **010000**, затем строят
дескриптор записи листа 1. **01073–01076** устанавливают:

| Адрес | Значение |
|---|---|
| 02000 | NAME, имя архива |
| 02001 | 0, конец пустого каталога |
| 02002 | `0x000001000000`, дескриптор начала со смещением 1 зона |
| 02377 | 1, число занятых слов каталога без заголовка |

**01077** записывает **одну зону** на U:Z; **01100** печатает `ЕСТЬ`.
Остальная память листа 1 не очищается; обнуления всего архива нет.
Команда не выполняет настройку `АРХ` автоматически. Проверка
`дай новарх 50 100 вася` подтвердила все четыре поля, а последующие
`арх вася,50,100` и `ктл` показали пустой каталог.

### Указать библиотечный каталог

```text
дай ктлбиб U Z
дай ктлбиб NAME
```

В двухаргументной форме **00755–00762** требуют U < **0100**,
Z < **02000** и записывают в **76012** дескриптор чтения листа 1:
`0010010000000000 | (U << 12) | Z`.

В одноаргументной форме **00763–00774** требуют идентификатор
(тип лексемы 5), ищут NAME в текущем архиве через **76006** и получают
его дисковый дескриптор в **77775**. Запрос использует режим
«получить дескриптор», с константой 76000 в 77774; содержимое файла
не загружается. После успешного поиска дескриптор также попадает в 76012.
Ошибка поиска передаётся резидентному принтеру.

Это изменение местоположения **КТЛБИБ в рабочем СБОЙ**, а не добавление
элемента в каталог и не подключение нового пользовательского архива.
Сохранения листа СБОЙ на барабан 27:031 здесь нет.
Проверены обе формы, а также отказ для U = 0100 и Z = 02000.

## СРАВН: сравнение файлов текущего архива

```text
дай сравн NAME1 NAME2
```

Аргументы — **имена файлов**, не адреса памяти. **00776–01013**
дважды вызывают **76006** в режиме получения дескриптора. Контрольное
имя архива берётся из **57770**. Первый дескриптор сохраняется в
**00776**, длина — в **00777**, поверх уже выполненных команд.
Второй остаётся в **77775**, длина — в **77773**.

**01016–01022** читают очередные зоны в листы **1 и 2**, затем сравнивают
все 1024 пары слов. Начальный М1 = **76001 = −01777**, адреса операндов
`03777(М1)` и `05777(М1)`; цикл включает оба конца зоны.

При совпадении **01023–01025** завершают сравнение, как только достигнут
конец **любого** файла. Поэтому `ЕСТЬ` означает равенство общего префикса
до конца более короткого файла: различие длин **не считается ошибкой**.
Это подтверждено файлами длиной 1 и 2 зоны с одинаковой первой зоной.

При первом различии **01033–01042** строят сообщение:

```text
НЕ РАВНО.001ЗОНА  АДРЕС 000017СРАВАД002017
```

Зона нумеруется **с 1**, первый адрес — смещение слова в зоне, второй —
это же смещение плюс **02000**. Например, последнее слово зоны даёт
`001777` и `003777`. Значения различающихся слов не печатаются.
`СРАВАД` — буквальный текст слова **01050 = 0x313020222024**;
исправлять его на «СПРАВА» при расшифровке образа нельзя.

## ЛЕНТ: настройки направления

```text
дай лент U ИМЯ
дай лент U СДВИГ Z
дай лент U СЧ
дай лент U ЗП
дай лент U ПЕРЕИМ V
дай лент U СМЕНАП V
```

**00404–00422** проверяют номер U маской 00321 и выбирают одну из шести
операций по ГОСТ-именам в **00462–00471**. Для ПЕРЕИМ, СМЕНАП и СДВИГ
следующий аргумент также проверяется маской 00321: допустимы только
значения **0–077**, хотя упаковка СДВИГ выделяет десятиразрядное поле.

| Опция | Адрес | Действие |
|---|---|---|
| ИМЯ | 00423 | Э50 0105 получает номер тома, Э50 0113 — смещение; печать `БОБ … СДВИГ … ЗОН` |
| ЗП | 00437 | Добавить признак 00472 и выполнить Э72 в 00444 |
| СЧ | 00440 | Убрать этот признак и выполнить Э72 |
| ПЕРЕИМ | 00444 | Э72 с упакованными направлениями и шаблоном 00473 |
| СМЕНАП | 00446 | Перед Э72 изменить биты операции маской 00474 |
| СДВИГ | 00450 | Э50 0112 с направлением и десятиразрядным смещением |

ИМЯ и СДВИГ проверены: частный том 2345 показывал смещение 0, затем
020, затем вновь 0. СЧ и ЗП вернули `ЕСТЬ`. ПЕРЕИМ 50 → 52 в проверенном
dispak завершился **АВОСТ 56** в **00444**, с управляющим словом
`3050115277000000`. Функциональность переименования и обмена направлений
через этот интерфейс не подтверждена.

## ДЕШ: преобразование редактируемого текста

```text
дай деш K
```

**00327–00342** принимают ключ K и проверяют систему в **57767**.
Поддерживаются только **АВТ** и **КОД**; в остальных случаях
**00343–00344** дважды печатают `НЕ ДАМ`. Начало текста задаётся
**00370 = 010000**. Это память редактируемого текста, не дисковые зоны.

Для АВТ контрольные байты — **0063** и **0140**, для КОД — **0172**
и **0175**. **00322–00326** ищут байт с разрушительным сдвигом рабочей
копии слова в 00402; цикл с М2 = −6 делает семь проверок, последняя
при исчерпанном шестибайтном слове проверяет ноль.

Алгоритм одного шага **00346–00367**:

1. Взять следующее слово текста. Если найден первый контрольный байт,
   искать второй в оставшейся сдвинутой копии. Оба найдены — завершить
   с `ЕСТЬ`; найден только первый — оставить слово и перейти к следующему.
2. Для слова без первого контрольного байта увеличить рабочий ключ
   с циклическим переносом на **`0x010101010101`**.
3. Получить кандидат `исходное слово XOR рабочий ключ`. Проверять
   контрольные байты тем же разрушительным поиском. Если обнаружен
   запрещённый результат, слово оставить; иначе записать кандидат.

Это не XOR с постоянным ключом для всего текста, и пропущенное слово
не обрабатывается повторно с другим ключом. Второй поиск получает
остаток после первого, а не заново исходное слово; из этого следует,
что при отсутствии первого кода проверка второго идёт уже по нулям.

Проверка в режиме КОД использовала два искусственных слова в 010000:
`0x2B252D2B252D` и `0x5A5B5A7B7C7D` (слово 01200 таблицы).
При K = 1 первое стало **`0x2A242C2A242F`**, второе осталось прежним
и завершило обход благодаря последовательности 0172 … 0175.
Без корректного конца текста ограничение области обхода не задаётся.

## Остальные подкоманды

### ШИФР, 00477

**Э50 0100** получает шифр задания в двоично-десятичной упаковке.
Маска **00301 = 0x0F0F0F0F0F0F** разносит шесть четырёхразрядных
цифр каждой половины в байты ГОСТ; печатаются все двенадцать цифр.
В проверочном паспорте
`шифр 412020` результат — **`412020000000`**.

### АЦПУ, 01053

```text
дай ацпу 'ТЕКСТ'
```

**01053–01055** требуют тип лексемы **1**, строку в кавычках.
**01056–01061** извлекают её длину в словах, ставят завершитель
после последнего слова и печатают через **Э64 01063**. Информационные
слова **01063–01064** указывают начало `2(М17)`, формат ГОСТ.
После вызова выдаётся `ЕСТЬ`. Числовой аргумент отвергается с `НЕТ`.
Это вывод на АЦПУ, поэтому отсутствие самой строки на терминале
не означает отказа команды.

### ПАУЗУ, 00061

**00061–00066** принимают N < **016**. Затем перед каждой паузой
уменьшают N и вызывают **Э50 7700**, A = **01000**. Для положительного
N получается N пауз; ноль возвращает управление сразу. В dispak одна
такая пауза длится **40,96 секунды**: 512 × 80 мс. Проверены N = 0
и отказ при N = 016; длительные паузы не запускались.

### ВРЕШ, 00077

Младшие четыре восьмеричные цифры аргумента разносятся в байты ГОСТ
процедурой **00704** и передаются в **Э63 2**, с двумя старшими нулевыми
байтами (в ГОСТ это символы `0`). Если значение аргумента
нулевое, берётся слово **00060 = 0x070707070707**, текст `777777`.
Это установка времени решения; в проверенном dispak Э63 2
не поддерживается и даёт **АВОСТ 3**.

### РАЗР, 00104

**Э61 0110** обращается к паспортному блоку **00110–00134**.
**00105–00107** проверяют разряд 47 слова 00115 (сдвиги вправо 46,
затем влево 47 разрядов), выбирая `НЕТ` или `ЕСТЬ`.

В dispak `e61()` лишь обнуляет семь слов с адреса обращения;
00115 попадает в этот диапазон. Поэтому наблюдаемое `ЕСТЬ` здесь
объясняется заглушкой, а не подтверждением исторической семантики
разрешения задания.

### КОДГО, 00070

Значение должно помещаться в байт. **00071–00073** заменяют им младший
байт **57536**, затем **00074** записывает весь лист НАБЛ на барабан
**27:037**. Проверены принятие **0377** и отказ для **0400**.

В имеющемся НАБЛ 57536 — слово остаточного фрагмента
`0640033103001431`, а не поле действующего терминального форматтера.
Назначение команды в другой редакции НАБЛ по одному имени «КОДГО»
не установлено; изменения протокола ввода/вывода этим запуском
не доказаны.

## Отдельный вход перекодировки

**00005** содержит `пб 1101(М10)`. Этот вход требует М10 = база **самого
перекодировщика**, в отличие от обычных команд ДАЙ с М10 = 056000.
М1 указывает слово текста, М2 — номер байта 0…5, М3 — возврат.
В логическом режиме нулевой A выбирает ГОСТ → ИТМ, ненулевой —
обратное направление; выбор делается условным переходом ПЕ.
В **01101** база М10 добавляется к индексу М2 для обращения к маскам.

**01102–01106** назначают входную/выходную таблицы в 01143–01144.
Параллельные таблицы: **01161–01201**, байты ГОСТ, и
**01203–01223**, соответствующие байты ИТМ. Между ними — нулевое слово
01202. **01131–01133** выделяют байт маской **01152–01157**;
**01115–01130** находят его позицию в первой таблице и берут байт
в той же позиции второй. **01134–01142** заменяют байт на месте,
переходят к следующему и увеличивают М1 после шестого.

Код **0377** завершает преобразование. Символ, которого нет во входной
таблице, также приводит к возврату через М3 (**01125**), а не заменяется
пробелом. Интерфейс и направление установлены статически; отдельного
динамического вызова через 00005 в проверках подкоманд не было.

## ФОРТ: Дубнинский монитор с обработчиком экстракодов

### Запуск, 01225–01242

Аргументы после `дай форт` не читаются. **01225** загружает собственную
зону ДАЙ в лист **36**, базовый адрес **074000**. Затем:

1. **01226–01230** вычисляют **75265** и назначают обработчик через
   **Э53 11**.
2. **01231** задаёт маску событий **0x000000040001**, события 1 и 19
   при нумерации разрядов с 1. **01232** вызывает Э50 7700 со словом
   **`0x1FFFFFE00028`**. В проверенном dispak это обычная пауза
   **3,2 секунды** (050 × 80 мс), поскольку старшие 24 бита не равны
   `0xFFFFFF`; вызов не доказывает установки асинхронного будильника.
3. **01233–01235** вызывают **Э62 53**, М15 = **023**, A = 0:
   маска перехвата **Э60, Э64, Э74**. Требуется ответ **077777**.
4. **01236** разрешает события (**Э53 14**), **01237** ещё раз
   читает исходный ДАЙ в 074000, восстанавливая исходные рабочие слова.
5. **01240** задаёт смещение направления **57** равным **0200**
   через Э50 0112. **01242** вызывает **СП 0100** через Э66 5,
   М15 = 0200. Номер СП содержится в следующей половине слова,
   `зп 100`; число 5 — параметр, не номер СП.

Запуск рассчитан на физические барабаны Дубны на направлении 57:
паспорт должен содержать `физо мб21` и соответствующий первый ЛЕНТ.
Для исходного 2248 общий адрес загрузки барабанного образа — смещение
0200; `--725` сохраняет эту геометрию при Э50 0112.

В **pult2068.b6** направление 57 подключено к **тому 2248**:
`лент 57(2248-371)`. ФОРТ заменяет исходное смещение 0371 на 0200;
том 2068 на направлении 40 служит источником самого ДАЙ, а Дубна
берётся с 2248. `make pult2068 SYSTEM_VOLUME=2148` выбирает вместо него
2148. В паспорте **pult.b6** направление 57 использует том **2250**,
частную исправленную копию 2248.

СП 0100 начинает загрузку Дубны физическим секторным чтением:
дескриптор **`4014010000210201`** читает барабан 21, дорожку 1,
сектор 2 в 02000–02377. При указанном размещении это слова
**01000–01377 зоны 0201 тома направления 57**.

### Область сохранения и диспетчер, 75265–75334

Локальные **01252–01264** становятся **75252–75264**. При входе
D = **75265**, слово **D−10 = 75253** содержит состояние с номером
экстракода **`opcode & 037`** в младших разрядах, а **D−8 = 75255** —
сохранённый адрес продолжения. **75265–75273** читают слово по адресу
продолжения минус 1, выбирают половину команды и сохраняют её в **75447**.

**75274–75277** маской **`0x000000F00FFF`** выделяют регистр и младшие
12 разрядов адреса, подставляют `мода` и исполняют её перед `уиа (М15)`.
Так вычисляется адрес для обслуживаемого экстракода. Маска не сохраняет
бит S короткой команды; это ограничение реконструкции, а не универсальный
декодер всех адресных форм БЭСМ-6.

**75317–75325** сохраняют М1 и М10–М14 в **75310–75315**.
**75326–75334** выделяют младшие 16 разрядов 75253 и сравнивают:

| Значение | Экстракод | Ветка, локальный / рабочий адрес |
|---|---|---|
| 020 | Э60 | 01337 / 75337 |
| 024 | Э64 | 01364 / 75364 |
| 034 | Э74 | 01363 / 75363 |
| Другое | — | 01335 / 75335, аварийное Э74 |

### Э60: текст на направлении 42

**75340** читает фиксированную зону **42:01523** в лист **35**, **072000**;
дескриптор находится в локальном 01464. Это источник текста программы.
Параметр `дай форт NAME` не меняет ни направление, ни зону и не вызывает
архивный поиск NAME.

**75341–75362**, **75407–75446** ведут позицию во входном слове и
формируют карточный буфер по адресу перехваченного Э60. Обычная ветка
**75345–75347** предварительно обнуляет 24 слова. Обработка байтов
включает выделение восьми разрядов, проверку чётности через ЧЕД,
добавление **0200** при нужном состоянии и упаковку со сдвигом по маске
из 75462. Коды **0341** и **0172** имеют отдельные ветви окончания текста;
передача по концу строки и дополнение буфера выполняются в 75440–75446.
Это собственный ввод ДАЙ; терминальные строки после приказа ФОРТ
не используются как карточный поток.

При исчерпании текста код также меняет продолжение через сохранённое
слово 75255 (**75356–75360**). Полный контракт карточного формата и
всех вариантов окончания требует отдельного сопоставления с Э60
Дубнинского монитора.

В проверке на паспорте pult2068.b6 перехват **сработал**: первый Э60
Дубны вошёл в **75265**, статус дал **020**, исполнение дошло до
**75340**, где отсутствие направления 42 вызвало **АВОСТ 42**.
При подключении частного тома 42 с текстом теста `fortran-dubna`
из дерева dispak ввод прошёл дальше: Дубна приняла карты и дошла
до первого Э64 в 02626. Полный прогон Фортрана не завершился.

### Э64, Э74 и выход

Ветка **75364–75372** переносит сохранённую половину команды в **75366**
через Э75 и выполняет её, затем берёт слово по М15, выделяет адрес из
левой половины и вызывает **76005** для вывода текста. Это не полная
реализация форматного описателя Э64: регистровые поля начала/конца
печатного диапазона не интерпретируются этой веткой как принтером.

Общий выход **75373–75405** повторно задаёт маску перехвата,
восстанавливает М10–М15 и М1 и делает **Э53 15**, возвращаясь с пропуском
перехваченного экстракода. Обращения к сохранённым полям на этом пути
используют **М1** как базу 074000, но явно устанавливает её только
ветка Э60 (**75340**). Поэтому сохранность базы на других путях —
существенное условие работоспособности обработчика.

Тест с направлением 42 воспроизвёл обе проблемы. Первый
**`Э64 104(М7)` в 02626** имел информационное слово
**`6400000074077777`**, диапазон от адреса в М15 до М17 − 1.
Обработчик выделил вместо него нулевой адрес начала, и на терминал
попал фрагмент машинного кода листа 0. Затем в **75375** М1 = **5**
вместо 074000: сравнение взяло постороннее слово, переход
`пе 1335(М1)` привёл в **01342**, а дальнейшее исполнение закончилось
**АВОСТ 31** в **40070**. Таким образом, работа перехвата и подачи
карт проверена, но обработчик Э64 и возврат после него несовместимы
с этим запуском Дубнинского монитора.

Отдельные запуски с **`лент 57(2148-371)`** дали те же результаты:
без направления 42 — АВОСТ 42 в 75340, с тестовыми картами на 42 —
ошибка обработки Э64 и АВОСТ 31 в 40070. В обоих случаях полные
инструкционные трассы побайтно совпали с соответствующими трассами
для 2248. Частная копия 2148 совпадала по SHA-256 с установленным
исходным томом. Паспорта, входы, вывод и трассы этих запусков сохранены
в `build/dai-probes-2148/`. Таким образом, замена тома Дубны с 2248
на 2148 не устраняет сбой в проверенном сценарии.

Ветка **75363** завершает задание через **Э74**, М11 = **074**.
Неизвестный код идёт в Э74 с М11 = **07777**. Код **75406** после
Э53 15 — аварийный хвост, а не штатное продолжение.

**00622–00634** упаковывают строку, **00635–00644** заканчивают её,
устанавливают указатель **56405** и вызывают форматтер НАБЛ **56400**.
**00652–00655** читают подтверждение через терминальные дескрипторы
**57763–57764**. **00672** раскладывает слово на шесть байтов;
**00704** выводит четыре младшие восьмеричные цифры с двумя ведущими
символами `0`; адресная разновидность **00711** сохраняет пять цифр.

**01465–01772** — остаточный фрагмент другого размещения кода.
Из разобранных входов к нему не найдено переходов. В **01770–01772**
есть последовательность записи листа 0 на системную зону 005,
но это не подкоманда таблицы ДАЙ. Область показана как шестнадцатеричные
данные; наличие декодируемых инструкций не делает её установленной
частью действующего монитора.

Проверки выполнялись последовательно вне песочницы в dispak из
`~/git/dispak/build/dispak/dispak`, с `--725`, отдельным временным HOME
и частными копиями 2068/2148/2248. Направления 50 и 51 использовали
созданные для проверок тома; рабочие архивы не изменялись. Трассы и входы
сохранены в `build/dai-probes/`. Исправления образа ДАЙ или эмулятора
для получения этих результатов не применялись.
