# БАВТ: дешифратор приказов и запуск программ

БАВТ — однозонный ассемблерный дешифратор третьего уровня ПУЛЬТа.
Он занимает **01051** на томах 2148/2248, **051** на 2068 и работает
в листе 33, **066000–067777**. ПУСК загружает его по **01416**,
если имя приказа отсутствует в таблицах НАБЛ и ПУСК.
Основной вход — **66007**, база — **М13 = 066000**.

БАВТ распознаёт собственные приказы, загружает служебные программы,
передаёт им параметры, а при отсутствии имени в своей таблице ищет
машинную программу в текущем архиве. Имя БАВТ одновременно обозначает
встроенный приказ запуска БЕМШ.

Образы 2148 и 2248 совпадают целиком. SHA-256 шестибайтного образа:
`ccdd304941e402f6a994d3e99670aae80be5c0c93c78e01a311d41fbcbebdd85`.
В 2068 сам БАВТ перенесён без изменения.

Все адреса, номера устройств/зон и параметры приказов далее восьмеричные.
Номера томов, количества элементов, размеры в словах и байтах — десятичные.
Отдельные значения слов и маски — шестнадцатеричные.

## Листинг и проверка

```sh
make bavt
python3 tests/bavt.py --dispak=/home/leob/git/dispak/build/dispak/dispak
```

Разметка — [syms/БАВТ.sym](../syms/БАВТ.sym); результаты сборки —
`build/БАВТ.lst` и `build/БАВТ.dump`. Размечены весь код, таблица имён,
сообщения, дескрипторы, самомодифицируемые поля и рабочий стек.

Проверки выполняются последовательно на временных копиях 2248/2068,
с отдельным HOME и небольшим архивом 2345. Входы, вывод и трассы —
`build/bavt-check/`. Для БЕМШ используется краткая трасса экстракодов:
полная инструкция за инструкцией заметно замедляет его длинную выдачу.
Исходные файлы томов проверяются по хешам после серии.

## Сканер и диспетчеризация

### Откуда берутся параметры

**66010–66011** вызывают резидентный **76016**; тело сканера находится
в СБОЙ. Он разбирает весь приказ в таблицу ссылок по **77331**
и отдельную таблицу значений. Устройство сканера подробно описано
в [разборе СБОЙ](sboy.md#скан-разбор-всего-приказа).
БАВТ устанавливает М12 на **66042**: этот адрес используется как возврат
при отсутствии первого идентификатора, чтобы обнулить признак **66713**
и повторить выборку первой лексемы.

М14 получает начало таблицы ссылок. **66013** устанавливает
М2 = М14 − 1. Подпрограмма **66067–66073** выполняет:

1. Увеличивает М2, читает очередную ссылку.
2. Выделяет её старшие три бита в **66711**, тип параметра.
3. Использует младший адрес ссылки, читает слово значения в **66712**.
4. Возвращается через М16. Сам М14 при обычном переборе остаётся
   указателем начала таблицы для передаваемой программы.

Типы — десятичные номера сканера:

| Тип | Содержание |
|---|---|
| 0 | Конец таблицы |
| 1 | Строка в кавычках |
| 2 | Целое |
| 3 | Вещественное число |
| 4 | Непропускаемый ограничитель, например `=` |
| 5 | Идентификатор |

**66710 = 5** задаёт требуемый тип имени приказа. Строка, число или
ограничитель на месте ожидаемого имени приводят к **66044**:
«НЕТ ИД В НАЧАЛЕ». Идентификаторы сканера содержат шесть символов ГОСТ,
пробелы справа. Длинные имена уже усечены сканером.

Обработчики сами решают, какие типы допустимы дальше. Например,
МАВТ требует тип 5 для имени массива; числовые параметры ФОРМ
проверяются по величине слова, без отдельного сравнения типа с 2.
`МАВТ 1`, `МАВТ 1.5`, `МАВТ 'А'` и `МАВТ =` дали «QU».

## Выполнение программы из архива

Промах таблицы ведёт на **66025–66033**. В **77770–77774** строится
параметрический блок резидентного загрузчика **76006**:

| Поле | Значение |
|---|---|
| 77770 | шифр текущего архива из НАБЛ **57770** |
| 77771 | имя из **66712** |
| 77772 | адрес загрузки: **67316 << 10**, здесь 0 |
| 77773 | лимит зон из **67317 = 020** |
| 77774 | 0 |

Ошибка поиска возвращает адрес сообщения в М1; **66033** передаёт
его в М15 и вызывает **76005**, затем **76002**.
Успех продолжает выполнение с **66034**.

**66036–66040** выделяют младшие 24 бита слова **00007** и сравнивают
с **67320 = `0x0000003a3a3a`**. Это три байта `:::` в ASCII.
При совпадении выполняется переход на **00007**, с сохранённой таблицей
параметров в М14. При несовпадении **66041** выбирает текст по **66063**:
**«НЕ БУДУ ВЫПОЛНЯТЬ»**. Наличие имени в каталоге само по себе
недостаточно для запуска.

В тестовом архиве проверены два образа. Первый имел командный тег
и слово 7 `пб 76002; уиа 35072(М3)`; он был запущен и вернулся в ПУЛЬТ.
Второй имел нули вместо слова 7; получен отказ до входа в программу.
Командные теги проверяются машиной при исполнении: правильная сигнатура
в слове с тегом данных приводит к «КОНТРОЛЬ КОМАНДЫ».

## Общий загрузчик и запуск Pascal-программ

### Обмен листами

**66202–66206** принимают дескриптор в A и отрицательный счётчик в М1.
Дескриптор сохраняется в **66207**, выполняется Э70, затем к нему
прибавляется **67321 = `0x000040000001`**: следующий лист и следующая
зона. Возврат — через М14. М1 = 0 выполняет один обмен, −1 — два,
−2 — три и т.д.

Входы РЕД, СЕРВИС, ЧИСТКА, ЛЕС, ЭХОЛОТ, СТРУК и ДЕМОС задают
первый дескриптор и счётчик, затем проходят через **66222**.
**66335–66340** загружают АДСИС в лист 36 по дескриптору
**0010360000400006**. Далее **66224–66226** берут слово 5 программы
как адрес стека, ставят **76002** в слово 1 будущего кадра и переходят
на **00007**. При настройке АДСИС также существует внешняя ветвь
**66270–66271**, читающая u56 z01361 в лист 36; её вызова из текущей
таблицы имён не найдено.

АЦПУ загружается особым путём в **66316** и входит по **74000**;
при нулевом либо ненулевом первом параметре переход фактически
приходит к этому же входу. См. [разбор АЦПУК](acpuk.md).

### Режимы СТАТИС и РРR

**66333** проверяет **66425**. Для обычной группы читается СТАТИС
из зоны **063**; РРR предварительно устанавливает этот признак
в **66423**, и читается зона **001**. Затем загружается АДСИС.
В рабочем стеке **67430…** готовятся аргументы режима.

Для СТАТИС, АЛГП, ГОСТ, ДУБНА, ВПАК и РРR **66363–66373** требуют
имя входного массива. Он читается в лист 34 через **76006**,
после чего **66374–66375** устанавливают **75211 / 75212**,
дескриптор и предел зон потока INPUT в АДСИС.

**66376–66407** принимают необязательный следующий параметр.
Если он есть, требуется тип строки; её первое слово помещается
в стек. При отсутствии берётся **67354 = `0x0f0f05080f0f`**.
Лишний параметр либо неправильный тип приводит к **67217**, «QU».

**66411–66422** настраивают главный кадр: берут адрес из слова 5,
вызывают **74036** для настройки пула внутренних зон, оформляют
слово 1 кадра и переносят подготовленные аргументы в его область
от смещения **012**. База кадра передаётся в М13, вход программы — 7.

ВРЕМ подготавливает только один аргумент, режим 4, и сразу выбирает
этот путь через **66411**. Введённое после ВРЕМ имя не используется.
Проверены `ВРЕМ` и `ВРЕМ ТЕСТ`: обе формы печатают время.

`СТАТИС` без имени успевает прочитать зоны 063 и 006, затем БАВТ
печатает «QU». Инструкции самой СТАТИС и вход **74036** при этом
не выполняются. `СТАТИС ПЕРВЫЙ` на тестовом массиве вошёл в АДСИС
и программу, выдав число строк, символов и их распределение.

## ФОРМ, ПОРЦ и режимы вывода

### ФОРМ

**66514–66574** последовательно разбирают до пяти необязательных
значений. Они хранятся в НАБЛ:

| Параметр | Поле | Ограничение по коду |
|---|---|---|
| конец строки | 57757 | меньше 0400 |
| длина строки | 57756 | меньше 0100000 |
| прогон / интервал | 57755 | меньше 010 |
| первый код конца текста | 57753 | меньше 0400 |
| второй код конца текста | 57754 | меньше 0400 |

Для длины строки сохраняется **1 − длина**, получаемое через
инверсию слова и прибавление 2. Это значение затем используется
как начальный отрицательный счётчик. При печати выполняется обратное
преобразование.

Если при входе параметров нет, **66551–66572** собирают сообщение
«КОН СТР=… ДЛИН=… ПРОГОН=… КТ=…». Цифры создаются рассеиванием
восьмеричных триад через **67361 = `0x070707070707`**.
Если параметры закончились после одного из присваиваний,
**66573** сохраняет НАБЛ на барабане 27:037 и возвращается.

Применение параметров последовательное. `ФОРМ 175 100000` печатает
«НЕТ», но уже записанный 175 остаётся: следующий ФОРМ показывает
`КОН СТР=175 ДЛИН=00000`. Ошибочная длина не отменяет первый параметр.
**66505** записывает изменённый НАБЛ на барабан даже на этом пути.

### ПОРЦ

**66306–66313** берут первое слово значения параметра и записывают
его в **56421, 56422, 76421, 76422**: начальный и текущий счётчик
у форматтеров НАБЛ и СБОЙ. При отсутствии параметра **66067** возвращает нулевое значение,
которое сохраняется как счётчик. Фрагмент **66314** устанавливает
**67337 = 016**, то есть 14 строк, но перехода к нему из текущего
обработчика ПОРЦ не найдено.
Затем сохраняются НАБЛ и СБОЙ на 27:037 и 27:031.

Здесь нет маски 037. Проверка `ПОРЦ 40` записала именно 040,
а `ПОРЦ` — 0. Руководство описывает значение по умолчанию 016;
текущий обработчик этого значения не устанавливает. Ноль отключает порционную остановку в проверенной
выдаче. Последующие параметры этой ветвью не разбираются.

### ПП, ППН, ПА

**67225 / 67232** читают сохранённый НАБЛ в лист 1.
Меняются его **02420**, резидентные **76420 / 76013**:

| Приказ | 02420 и 76420 | 76013 |
|---|---:|---:|
| ПП | 3 | 3 |
| ППН | 0 | 1 |
| ПА | 2 | 2 |

ПА предварительно заменяет постоянную **67350** значением 2 и входит
в ПП. **67237–67242** записывают СБОЙ в 27:031 и изменённый НАБЛ
в 27:037. Настройка действует в последующих приказах.
В тесте архивная диагностика после ПА исчезает с терминала,
после ППН и ПП возвращается.

## СБУФ, ЗКАН, КОНКАТ и ДИСПАК

### СБУФ

**66322–66332** читают первый параметр, маскируют его
**67341 = `0x00000000001f`** и строят счётчик для общего обмена.
Без параметра, при нуле и при числе, кратном 040, выводится «НЕТ».
При единице читается **0010040000270000**: барабан 27, зона 0,
лист 4. Далее последовательно читаются следующие зоны/листы.
Максимальный ненулевой результат маски — 037 зон.
Сообщение «!ДИНАМ. ОБМЕН. … ЛИСТОВ» имеет отдельную ветвь
**66210**; переход из **66326** к ней после уже выполненной проверки
на ноль в **66325** избыточен при неизменном значении **66712**.

### ЗКАН

**67244** выполняет **Э61 021**, затем проверяет
**M[026] & `0x400000000000`**. Нулевой результат ведёт к «НЕТ»,
ненулевой — к «ЕСТЬ». В проверенном dispak получено «НЕТ».
В самом БАВТ нет чтения массива или изменения каталога на этой ветви.

### КОНКАТ

Синтаксис по коду:

```text
КОНКАТ первый_массив слово_маркер второй_массив
```

**66605–66615** загружают первый массив с **010000**.
**66616–66625** берут слово-маркер и сравнивают с каждым **целым
машинным словом** массива. Поиска по смещённым байтовым подстрокам
здесь нет. Совпадение включает пробелы и все остальные разряды слова.
Без совпадения **66626–66634** печатают «!НЕТ ОБРАЗА».

При успехе **66635** сохраняет адрес найденного слова в М6.
**66636–66640** округляют этот адрес вверх к следующему листу:
`page = (address >> 10) + 1`, `М7 = page << 10`.
Туда **66641–66651** загружают второй массив. **66652–66656**
переносят его вперёд по одному слову Э75, начиная с позиции маркера.
Второй массив заменяет маркер и последующий текст первого массива.
Результат остаётся в памяти; выводится «ЕСТЬ».

Счётчик М10 задаётся инверсией **числа зон × 1024**. ЦИКЛ проверяет
ноль до увеличения, поэтому фактически копируются **N × 1024 + 2**
слова. Это подтверждено трассой: для второго массива длиной одну
зону выполнено 1026 Э75, назначения **010001–012002**.
В тесте слово МЕТКА по 010001 заменилось словом ББББББ второго массива.
Сканирование первого массива также имеет два дополнительных слова
к его зонной длине. Назначение такого запаса самим кодом не поясняется.

### ДИСПАК

**66666–66676** при наличии имени сначала читает массив в **010000**.
Без имени используется текущая память. **66677–66700** вызывают
**Э50 7701**, A = 010000: формирование новой задачи из подготовленного
текста. **66701** сравнивает возвращённое A с **010000**:
равенство означает «ЕСТЬ», остальное — «НЕТ».

Проверка на коротком тексте, не являющемся паспортом задачи, дала
«НЕТ». Путь вызова экстракода установлен; успешное создание и выполнение
новой задачи этим опытом не проверялись. Для пакетной цепочки приказов
обёртку формирует ВПАК в СТАТИС; затем вызывается ДИСПАК.

## ПАСКАЛ, ПАС и МАВТ

**66003** читает **67315 = `0010330000400050`** поверх самого БАВТ.
Следующая инструкция по 66004 уже принадлежит загруженному ПАСК.
Его разбор находится в `~/git/besm6/pasauto-re/paskal.b6`.

**67024** предварительно читает барабан 17, зону 037, в лист 0,
сверяет слово 3 с именем ПАСКАЛ и либо входит в сохранённый образ
по 7, либо переходит на **66003**. В проверке ПАС загружен компилятор
из восстановленного 2068 с приглашением 9.(09.12.88).
Это проверка загрузки; входной буфер этого опыта не содержал
корректной Pascal-программы.

МАВТ принимает ноль либо одно имя массива, проверяя тип 5 и отсутствие
лишних параметров. **66732–66757** ищут пару байтов **063,0140**
в исходнике от **010000**, с байтовой выборкой **67016 / 67021**.
М2 первоначально равен 040000; с семантикой ЦИКЛ просмотр включает
040001 слов, от 010000 до 050000 включительно. При отсутствии пары
печатается «НЕТ СИМВОЛОВ КОНЦА».

После нахождения **66760–66766** вычисляют число зон исходника
с вычитанием 3 и сохраняют текст в барабан 23 от зоны 0. На томе 2048
загружаются u40 z01600–01604; на остальных — u57 z0600–0604.
**66776** проверяет слово **04251** по **67373**.
Успех копирует пять зон на барабан 10 от зоны 6 и входит по **06770**.

На стандартном `pult2068.b6` смещение u57 = 0371 превращает чтение
0600 в системную зону 01171. Синтетический признак конца позволил
пройти сохранение текста и все пять чтений, затем получить
«НЕТ АВТОКОД ТРАНСЛЯТОРА». Подробности — [doc/mavt.md](mavt.md).
Трансляция корректной программы данным опытом не подтверждена.

## БАВТ: запуск БЕМШ и его продолжения

### Параметры и сохранение памяти

**67030–67053** различают наличие имени по типу первого параметра.
При имени выбирается **67054**, чтение исходника в лист 6, то есть
с **014000**. Без имени **67064** сохраняет текущий исходник из
области **010000…** переносом с помощью **66437–66460**.
Процедура имеет два направления переноса в зависимости от взаимного
расположения входного и выходного указателей; используется также ЗАГР.

Внутренний разбор необязательного адреса в **67042–67051** ожидает
отдельную лексему со значением **67254 = 013**, то есть знаком `-`,
и следующую лексему типа 2,
сохраняют адрес в **67255** и выбирают последующий загрузчик
**67202**. Без такой пары продолжение — **67215**.
[Руководство](PULT-User.md#pdf-042) описывает `БАВТ [имя] [* адрес]`.
В исследуемом коде проверяется минус; сканер 76016 сворачивает минус
перед числом в отрицательное целое. Проверки `БАВТ * 100` и
`БАВТ - 100` обе дали «QU». Таким образом, ветвь запуска с адресом
присутствует, но эти формы ввода до неё не доходят.
Область **67252–67257** хранит имя, знак, адрес и выбранные ветви.

### Устройства и начальный вход

**67070** с ключом **KEYE72 = `0x4b4559453732`** устанавливает
адрес обработки Э74 **66004**. Это завершающий обработчик; механизм
маски перехвата произвольных экстракодов здесь не используется.

**67071–67101** выбирают одну из четырёх операций:

| u40 = 2068 | u30 занят | Операция по 67277+k |
|---|---|---|
| да | нет | переименовать 57 → 30 |
| да | да | обменять 57 и 30 |
| нет | нет | переименовать 40 → 30 |
| нет | да | обменять 40 и 30 |

Признак выбора хранится в **67313**, проверка тома 2068 — по
**67404 = `0x000000002068`**, в двоично-десятичном представлении.
**67102** задаёт u30 смещение **0200** через Э50 0112.
**67103–67104** читают u30 z01747 в лист 0. С геометрией `--725`
это физическая зона **(0200 + 01747) & 01777 = 0147**.
Затем **67105–67106** ставят через Э75 в слово **01274** команду
`пб 67111`, выбирают продолжение **67154** и входят в БЕМШ по **01100**.

Проверенный БЕМШ затем читает u30 z01750–01752 в листы 34, 36, 37.
Э74 действительно возвращает управление через **66004**:
восстанавливаются резидент и НАБЛ с барабана.

### Сохранение индексов и переключение обратно

**67111** сохраняет входное М13 в **67414** и входит в **67131**.
**67113–67122** сохраняют М1–М15 в **67260–67274**, аккумулятор
в **67275**, М17 в **67276**, адрес возврата в **67130**.
**67123–67127** выполняют обратную выборку сохранённых значений,
после чего **67121–67122** восстанавливают стек и продолжают вызов.

**67131–67145** временно восстанавливают НАБЛ в лист 32 (064000),
используют его форматтер через относительный вход 0400,
устанавливают последующие точки продолжения и возвращаются в БЕМШ
по **070000**. Это отдельный путь для врезанного перехода из 01274.

**67146–67153** восстанавливают СБОЙ из 27:031 и НАБЛ из 27:037,
затем переходят через смещение **67413**. Эту процедуру использует
также вектор **66004**, установленный для Э74.

**67154** выдаёт текст по абсолютному адресу **04761**, проверяет
абсолютное **01177** и выбирает сообщение о конце трансляции либо
счёта. **67161–67171** восстанавливают смещение и назначение устройств,
ещё раз загружают СБОЙ/НАБЛ, возвращают обработчик исключений
**76000** через Э50 0103 и переходят к выбранному сообщению.

Обратные операции находятся в **67303–67306**, значения смещений —
**67307–67312**. Здесь обнаружены две несогласованности:

- При u40 = 2068 и занятом u30 стартовая операция **67300** меняет
  **57↔30**, а обратная **67304** меняет **40↔30**. Значение слова
  67304 — **`0x620018fc0000`**; обратной к стартовой операции было бы
  **`0x62f018fc0000`**. Это перестановка других устройств.
- Для обоих вариантов с u57 восстанавливаемое смещение равно 0.
  Исходное **0371** штатного задания нигде не сохраняется.
  Для двух вариантов с u40 записано фиксированное **01000**.

Таким образом, выход предполагает исторические смещения и содержит
ошибочную обратную перестановку для варианта 2068 с занятым u30.

**67172–67201** печатают «КОНЕЦ ТРАНСЛЯЦИИ» и выбирают продолжение
по **67257**. **67202–67205** устанавливают обработчик Э74 **67206**,
читают девять зон барабана 27 от 0 в листы 0–10 и переходят на
адрес счёта из **67255**. **67206–67216** восстанавливают базы,
печатают «КОНЕЦ СЧЕТА», возвращают обработчик Э74 ПУЛЬТа и входят
в резидентный возврат. Общая диагностика «QU» использует тот же
восстановительный выход **67215**.

### Результат проверки совместимости

На частных томах подтверждены обмен 57↔30, установка смещения 0200,
вход БЕМШ и возврат через Э74 с восстановлением резидентных листов.
Однако выдача по **04761** содержала длинную последовательность нулей.
При обычном размере порции возникало «ИДТИ?»; отрицательный ответ
прерывал выдачу и возвращал монитор.

С `ПОРЦ 0` выдача дошла до обратной перестановки **67163 / 67304**.
После неё монитор попытался перечитать ПУСК с u40 z040 и получил
постороннее содержимое. Следовали **АВОСТ 000030** по **02005**
и «ЗАТЕРТО СПО».

Причинная связь проверена на отдельной одноразовой копии 2068:
замена только **67304** на обмен **57↔30** устранила эту аварию,
сеанс завершился штатным «ВРЕМЯ РЕШ». Исходные тома и генератор 2068
в этом опыте не менялись. Проблемы длинной выдачи по 04761 и
восстановления смещения u57 этим исправлением не устраняются.
Полная трансляция с дополнительными адаптациями проверена следующим
примером. Последующий счёт полученного модуля не проверялся.

### Успешная трансляция текста в режиме СИС БЕМ

Воспроизводимый сеанс — [tests/bemsh.txt](../tests/bemsh.txt),
запуск на одноразовых дисках — [tests/bemsh.py](../tests/bemsh.py):

```sh
python3 tests/bemsh.py --dispak=/home/leob/git/dispak/build/dispak/dispak
```

Нужны подготовленные `build/volumes/2248` и `build/volumes/2068`.
Тест создаёт частный архив 2345 на u50 и выходной том 2222 на u43.
Исходные тома проверяются по SHA-256 и остаются неизменными.
Листинг, трасса и выходные тома сохраняются в `build/bemsh-check/`.

Сначала создаётся архив и выбирается режим формирования текста:

```text
дай новарх,50,100,вася
арх вася,50,100,100
сис бем
форм 0
порц 0
з бтест(1)=тт
ВВД◇◇◇‾
ТЕСТ     СТАРТ    '1000'‾
         СЧ       КОНСТ‾
         ЗП       РЕЗ‾
КОНСТ    КОНД     В'123'‾
РЕЗ      ПАМ      1‾
         ФИНИШ‾
КВЧ◇◇◇‾
ТРН◇◇◇‾
БЛМАК‾
0-0‾
ЗОНМОД430000  0004‾
КНЦ◇◇◇‾
```

После последней карты вводятся `//` и ETX (Ctrl-C, U+0003), затем
`БАВТ БТЕСТ`. В файле сеанса ETX сохранён буквально. Знак **‾**
(U+203E, ГОСТ 0115) завершает каждую карту: обычные переводы строк
при вводе `З …=ТТ` удаляются. Это соответствует
[описанию режима БЕМ](PULT-User.md#pdf-042).
`БЛМАК` позволяет обойтись без библиотеки макроопределений;
`ЗОНМОД430000  0004` направляет модуль в зону 0 устройства 43.
Выдача листинга идёт на АЦПУ, в тесте её показывает ключ dispak `-p`.

Для штатного возврата этого примера тест вносит пять проверяемых замен
только в свою копию зоны 051:

| Адрес БАВТ | Исходное слово | Замена | Назначение |
|---|---|---|---|
| 67304 | `0x620018fc0000` | `0x62f018fc0000` | обратный обмен 57↔30 |
| 67310 | `0x000000018000` | `0x0000000180f9` | восстановить смещение 0371 |
| 67106 | `0x09000003d2bc` | `0x090000090000` | сохранить исходное слово БЕМШ 01274 |
| 67412 | `0x00000000026c` | `0x000000000271` | после Э74 продолжить с восстановления устройств по 67161 |
| 67421 | `0x00002125453f` | `0x00000000027a` | выбрать сообщение по 67172 |

Последние три замены адаптируют возврат к БЕМШ 06/78. Его исходное
**01274** содержит `по 1271; мода`; подмена переходом в БАВТ приводит
к **070000**, где у этой версии находится чтение очередной записи.
При компиляции теста получалось повторное чтение и многократная запись
одного модуля. Сохранение исходного слова позволяет завершить трансляцию
через Э74. Путь **67154** обращается к несовместимым абсолютным полям
**04761** и **01177**; пример пропускает его и выбирает сообщение
о завершении трансляции явно. Это адаптация сеанса трансляции без
последующего запуска программы. Изменения в генератор 2068 не вносятся.

Получен результат:

```text
ЧИСЛО ОШИБОК=0000. МАКС СЕРЬЕЗН=0.
МОДУЛЬ  ТЕСТ    ЗАПИСАН  В  ЗОНЫ  С 430000  ПО  430000
КОНЕЦ ТРАНСЛЯЦИИ
-
18.10.86    ВРЕМЯ РЕШ:   00000 СЕК
 КОНЕЦ ЗАДАЧИ
```

Листинг даёт **01000**: `сч 1001; зп 1002`, **01001**:
`0x000000000053`, **01002**: резерв одного слова. В записанном
объектном модуле проверены начальный адрес **01000**, длина 3 слова,
обе команды и константа. Также проверены однократная запись модуля,
отсутствие АВОСТ и нормальное завершение задания после возврата в ПУЛЬТ.

## ЗАГР и дополнительные пути

**66426–66431** разбирают необязательное имя. Без имени
**66432–66460** подготавливают текущую память; с именем
**66462–66472** загружают массив через 76006. **66473–66476**
читают **u57 z0144 в лист 20**, задают KEYE72 с выходом через
резидентный обработчик и входят в загрузчик по **040600**.

При u57 = 2248−0371 фактически читается системная зона **0535**.
Проверка ЗАГР в этой конфигурации дошла до постороннего кода и
«КОНТРОЛЬ КОМАНДЫ»; работоспособного загрузчика по указанному месту
не установлено. В [§ 23.2 руководства](PULT-User.md#pdf-043) назначение
приказа — подать текущую память или архивный массив загрузчику БЕМШ.

Остаются следующие небольшие фрагменты, не выбираемые текущей таблицей
имён. Их команды полностью присутствуют в листинге:

| Вход | Содержание |
|---|---|
| 66234 | две зоны с u40 от 071, затем общий Pascal-запуск |
| 66242–66260 | обмен по слову 1, инициализация 76000, восстановление Э74, сообщение «ВЫХОД ИЗ ПОПЛАНА В ПУЛЬТ» |
| 66261 | задаёт М1 = 0227 и входит в 66234, где М1 тут же заменяется на −2 |
| 66270–66271 | внешний образ АДСИС u56 z01361 → лист 36 |
| 66272–66303 | загрузка именованной программы из архива, затем общий запуск |
| 66477–66501 | 12 зон u40 от 01436 → листы 0–13, вход 1 |
| 66504 | непосредственный переход на 1 |

Некоторые из этих входов имеют внутренние переходы друг к другу.
Их исторические имена по одному положению в образе не устанавливаются.
Неиспользованные дескрипторы **66227 = u56 z0541**,
**66230 = u56 z0552** и **67360 = u56 z01321** также выделены в данных.
Область **67430–67777** исходно нулевая и используется как рабочий стек.

## Полнота и пределы

Разбор охватывает все 34 пары таблицы имён, общие процедуры,
завершающие обработчики, внутренние невызываемые из таблицы фрагменты,
данные и рабочие области зоны. Сканер 76016 и тела загружаемых
Pascal-программ описываются в соответствующих отдельных разборах.

Воспроизводимая серия содержит 28 случаев, включая ожидаемые отказы
u66 и завершающего пути БЕМШ. Успех такой проверки означает соответствие
наблюдаемому результату, указанному в тесте. Трансляция автокода,
корректная пакетная задача и успешный счёт через ЗАГР ею не доказаны.
