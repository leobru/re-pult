# СЕРВИС: аннотированный исходник и точная рекомпиляция

[pascal/servic.pas](../pascal/servic.pas) — читаемая версия декомпиляции
`/home/leob/src/bega-re/servic.pas`. Она воспроизводит сборку `SERVIC211188`
с тома **2148**, зоны **01031–01033**, выбранную для зон **031–033** тома
2068. На 2248 находится другая сборка, `SERVIC031286`; её сравнение описано
в [COMPARISON.md](../COMPARISON.md#сервис-0103101033).

Переменные и подпрограммы получили смысловые имена. Комментарии объясняют
обмен с ОС, устройство печатного буфера, поиск и выдачу строк, подключение
томов и обращения к АРФА. Сохранены порядок объявлений, числовые константы,
метки ассемблерных вставок и операции с аккумулятором. В этом диалекте
`x := ;` принимает значение аккумулятора, а `x := x` перед `CODE` может
подготовить его для следующей команды. Длина значимой части имени — шесть
символов.

Адреса и номера зон ниже восьмеричные, количества десятичные, отдельные
машинные слова записаны в шестнадцатеричном виде.

## Проверка

```sh
make checkservic DISPAK=/home/leob/git/dispak/build/dispak/dispak
```

[tests/servic.py](../tests/servic.py) создаёт временные копии дисков, помещает
в копию 2068 компилятор Паскаль-автокод 9 от **17.05.88** из зон
01101–01114 тома 2248 и компилирует исходник с сохранением трёх зон:

```text
арх вася,50,100
пас сервис - па зонгп 500300 3
конец
```

Автокод ИТМ подключается штатным способом через НУ 057, том 2248,
смещение 0371. Историческая дата **21.11.88** задаётся подменой `localtime()`
из [tests/servic/compile-date.c](../tests/servic/compile-date.c).
Результат компиляции сравнивается пословно целиком, без исправлений
сгенерированного образа и без исключённых слов.

Получено полное совпадение **3072 слов** с дисковыми образами 2148 и 2068:

| Часть | Адреса | Слов | Различий |
|---|---|---:|---:|
| Заголовок, константы и программа | 00000–05617 | 2960 | 0 |
| Остаток последней зоны | 05620–05777 | 112 | 0 |
| Все три зоны | 00000–05777 | 3072 | 0 |

SHA-256 всех трёх зон, по шесть байтов на слово, старший байт первым:

```text
c40f80afc0188aee0bded6d5f0ebe7565b4a7db3c6c5407f0d6a0d8bb1971d22
```

В `build/servic-rebuild/` сохраняются вход сеанса, протокол компиляции,
образы `original.bin` / `generated.bin` и `comparison.json`. Проверка также
подтверждает неизменность исходных дисков. Бинарное совпадение охватывает
все ветви программы; выполнение всех услуг ОС отдельно не проверялось.

## Выбор компилятора и ассемблерного входа

Майский компилятор воспроизводит эту сборку точно. Декабрьский компилятор
9 от 09.12.88 даёт такой же размер, но другую генерацию в девяти словах:

| Адреса | Майская генерация | Декабрьская генерация |
|---|---|---|
| 03631 | `008000203005` | `00800a203005` |
| 04175–04201, 04277–04301 | `ПБ` в таблицах `CASE` | `ПБ (М10)` в тех же таблицах |

В исходной декомпиляции вставка по адресу 01214 записана как `12пвф`.
При компиляции `Ф` разрешается в 75675. Дисковая команда вызывает вход
**74066** АДСИС, поэтому в аннотированном исходнике здесь явно записано
`12пв74066`. Это единственное изменение машинного назначения команды
по отношению к предоставленному тексту. Оно восстанавливает дисковое слово
`acf836000000`. Вход 74066 передаёт управление к услуге привязки ввода;
см. [АДСИС](adsis.md).

### Состояние и вход

Инициализация начинается с 05236. База редактируемого текста `txtbuf`
равна 010000, выходной текстовый буфер размещён с 072000. Параметры
из НАБЛ 57640–57656 копируются в 70001–70017. Ячейка 57757 задаёт
разделитель строк; нулевое значение заменяется кодом 0175.

`getcmd` оставляет первые три буквы слова и пропускает остальные.
Диспетчер в 05333 сравнивает полученное слово с константами ALFA.
05322 запрашивает новый приказ, 05324 разбирает уже введённый ответ.
Пустой приказ возвращает в ПУЛЬТ через 76002.

| Приказ после сокращения до трёх букв | Обработчик |
|---|---|
| ВРЕ | Время процессора и оставшееся время |
| Н, НАЙ | Поиск образца |
| С | Выдача текста |
| В, ВСТ | Вставка текста |
| П, ПОЛ | Начальная колонка выдачи АЦПУ |
| А, АЦП | Печатный буфер; аргумент О… выбирает остаток бумаги |
| ТРА, БОБ, РЕС, ОТК, ПАР, МОТ, НАП | Тракты, тома, ресурсы и пароли |
| SYS | Опрос системных текстов и сигнатур |
| ОБЛ | Принятие области АРФА |
| МАГ, ДИС | Занятость физических устройств |
| ВЫБ | Удаление задачи из каталога по номеру канала |
| ПУЛ | Перезагрузка ПУСК с НУ 040, зона 040 |
| ИНФ | Справка |
| ППН, ПП, ПА, НП | Запись 1, 3, 2, 0 в режим вывода 76013 |
| КОН, латинская F | Завершение задачи через Э62 |

Во встроенной справке выдача строк названа «СПИС». В диспетчере этой
сборки для неё есть только `С`: слово `СПИС` сокращается до `СПИ`, для
которого ветвь отсутствует. Режим `direct` включается, если первым
разобранным словом вызова служит латинская A; он убирает нумерацию строк.

### Поиск и вставка

НАЙ принимает диапазон строк и образец в апострофах. Апостроф внутри
образца удваивается. `hits[0]` содержит число сохранённых результатов,
`hits[1..100]` — номера строк. Общее число совпадений может превышать 100.
Поиск потребляет символы INPUT при сравнении; это существенно при
рассмотрении перекрывающихся образцов.

`С НАЙ` преобразует сохранённые номера строк в список интервалов и убирает
повторные номера. При обычной выдаче по умолчанию выбран интервал
1:100000. После списка можно задать другой символ разделителя строк.

ВСТ переписывает текст, вставляя после указанной строки содержимое F.
Файл F связан заголовком программы с барабаном 027, зоной 0. После сборки
текста программа читает сформированные зоны с барабана 026 через Э70.
Счётчики отдельно учитывают вставленные строки и символы, а также полную
длину результата.

### Печатный буфер

`rdprt` получает буфер Э62 041 порциями по 1024 слова. Каждая порция
обрабатывается четырьмя вызовами `decblk` со смещениями 0, 256, 512, 768.
В первом заголовке используются младшие 12 бит длины и следующие 15 бит
сдвига; специальные ветви извлечения байтов находятся в L1435–L1455.

Распаковщик пропускает коды 0 и 97, кодом 124 завершает блок, кодом
125 завершает текст. Коды меньше 97 преобразуются вычитанием единицы.
Код 127 повторяет предыдущий символ заданное число раз. Значение больше
128 задаёт колонку, до которой добавляются пробелы. Остальные управляющие
коды формируют конец строки. L1470 объединяет последовательные переводы
строк и ведёт текущую колонку.

`prtout` считывает буфер один раз за запуск СЕРВИС, затем пользуется
сохранённым текстом. ПОЛ задаёт первую из 79 выдаваемых колонок.
